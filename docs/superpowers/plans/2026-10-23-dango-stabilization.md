# 团子近期稳定性与陪伴体验推进计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or executing-plans to implement an approved sub-plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先让团子稳定认清身边的人、减少无效确认和不合时宜的接话，再推进自主行动。

**Architecture:** 延续现有感知、身体、大脑、内心层和沙盒结构。身份判断采用已有身份板方案；在场确认和聊天分寸分别验收，避免一次同时改视觉、时序和提示词而无法归因。

**Tech Stack:** Python、pytest、YOLO、DINOv2、无障碍聊天读取、现有大脑沙盒和管理面板。

**Spec:** 本文是阶段推进总计划，不是新增行为的详细设计。依据如下；身份板直接使用已有实现计划，其余子项先补相应设计和实施计划，再改代码。

## Global Constraints

- 主目录保持 `main`；各子项使用独立 worktree。已有身份板 worktree，接手前先确认其进度，避免重复实现或覆盖别人的未提交改动。
- 修改完成按 `CLAUDE.md` 合并、推送；主目录更新前确认 19390 / 19391 / 19392 均未监听，并检查本地改动及未跟踪文件是否冲突。
- 游戏操作沿用截图、UI 无障碍读取和模拟输入，不读游戏内存、不抓包。真机交互前后按 `docs/game-ops.md` 截图确认状态。
- 身份板保持现有设计的 `enabled = false` 退路；代码合并不等于本机开启，更不等于真机验收完成。
- 记忆、好友原话、真人录像、裁图和本机配置留在现有私有仓库或 gitignore 目录；公开报告只写聚合指标与匿名案例。
- 地图交互图标最小版只认、不点；共享空间「加入」永远不点。轮盘锁定格不动，下线恢复用户配置。
- 不改身份底线，不把「像人」等同于更频繁开口，不通过固定回复比例或一律延长等待制造改善。
- 本轮不重写架构、不换大模型供应商、不训练新认人头、不增加自主跑图。后续扩展遵循长期路线图，需另立设计。

## Review Focus

1. 标签跳动、镜头平移和遮挡不能立即把好友变成陌生人，也不能污染底库：由任务 1 验证。
2. 稳定在场、真正离开、输入框拦住呼喊三种情况必须分开，减少呼喊不能靠漏报离开：由任务 2 验证。
3. 好友互聊、直接叫团子、认真诉苦和短句连发不能使用同一种接话策略：由任务 3 验证。
4. 界面挡住、互动没完成、备用模型不可用时必须准确报告，不能把工具调用成功当成游戏操作成功：由任务 4 验证。
5. 退出、模型降级、开关回退及多人素材不足时，结论必须保留适用范围，不能用单测或少量回放代替实测：由任务 0、1、4、5 验证。
