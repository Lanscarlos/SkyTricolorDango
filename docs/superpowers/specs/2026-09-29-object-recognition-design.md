5. 物品模式里 Claude 判定"这个人物框其实是先祖"时**自动改**，一律列进待核对清单

## §1 类别和标注规则

`[perception] classes` **末尾追加**（YOLO 标注存的是编号，追加才不会让旧的 311 帧标注失效）：

| 编号 | 类别 | 中文 | 标 | 不标 |
|---|---|---|---|---|
| 6 | `bench` | 座位 | 明显给人坐的：长椅、石凳、秋千座、摆好的坐垫 | 台阶、石头、地面 |
| 7 | `bonfire` | 篝火 | 燃着的篝火堆（含玩家放的篝火道具） | 蜡烛、烛火堆、灯笼 |
| 8 | `instrument` | 乐器 | 摆在场景里、没人拿着的乐器（钢琴、竖琴架……） | 玩家手里的乐器（那是人的状态） |
| 9 | `spirit` | 先祖 | 发光的先祖灵魂（没收集时站在原地的）、先祖回忆里的半透明人形 | 玩家、团子、宠物、跟着玩家的小光团 |

框：框住整个物品，被挡住就框露出来的部分；框高 < 15 像素不标；先祖只框身体、不含头顶光效。

检测器照旧优先读模型文件里的类别名：用 v4（6 类）时物品功能自然为空，不报错、不用改配置。

## §2 标注流程：物品模式

```bash
python -m skydango perception label <数据集目录> --objects [--model 模型]
```

- 对**已标好人的数据集**（`images/{train,val}` + `labels/`）跑，不是录像目录。新录像先走原来的 `--assist`（标人），再对数据集跑 `--objects`。
  和 `--assist` / `--spin` / `--from-runs` 互斥
- 每张图给 Claude：坐标网格 + **已有人物框**（标注文件里的 `player` / `player_unlit`，灰细框，编号 P1、P2…）+ **物品候选**（彩色，编号 1、2…；
  `--model` 时是模型认出的物品类框，没有模型时没有候选，Claude 按网格直接框）
- Claude 回答：每个候选 对 / 改类别 / 修正框 / 不是物品 / 重复；漏掉的物品（类别 + 框）；**哪些人物框其实是先祖**（P 编号）
- 写回：
  - 先把整个 `labels/` 复制到 `_backup/labels-<时间>/`
  - 编号 0~5 的行**原样保留**，只有被判成先祖的人物行改成 `spirit`；编号 6~9 的行整体换成这次的结果（重跑安全）
  - `data.yaml` 写成 10 类
- 沿用 `assist.Reviewer`（分批、并发、缓存、额度用完重跑接着做）；物品模式有自己的提示词版本号和缓存目录（`_assist_objects/`），和标人的不串
- 预览 `_preview_objects/`：座位蓝、篝火橙、乐器粉、先祖白；Claude 补的框虚线；人改先祖红虚线
- 待核对清单 `_assist/objects.md`：人改先祖的帧、Claude 补了框的帧、没核对成的帧排前面
- 成本估计：311 帧约 100 万输入 / 55 万输出 token，15 路并发二十分钟左右

录数据建议（写进训练进度文档）：每类至少 50 个框、2~3 张地图；专门去有长椅、篝火、钢琴、先祖的地方各录一段；花地图（先祖多）已有，补标即可。

## §3 运行时：告诉大脑

**感知层**（`vision/perception.py`）
- 物品框照常进追踪器；追踪器的跨类只在 `player` ↔ `player_unlit` 之间，物品和人不串
- `objects(now) -> list[Thing]`：最近一帧的物品，轨迹 `hits ≥ object_min_hits`（3）才算；暂停中或最近一帧超过 1 秒（`PEOPLE_STALE`）返回空；
  方位同 `people()`（框中心三等分）；**远近按框底边**：底边 ≥ 画面高 × `object_near`（0.85）近、≥ `object_far`（0.65）中、否则远（**未在真机标定**）；
  排序：左 → 前 → 右，同一边近的在前
- `overlay()`：物品框 `kind` = 类别名，`label` = 中文名
- 先祖成了单独一类，自然不算陌生人

**`Thing`**（`vision/people.py`，和 `Person` 放一起）：`track_id, kind, box, side, distance`；`OBJECT_NAMES = {"bench": "座位", "bonfire": "篝火", "instrument": "乐器", "spirit": "先祖"}`；
`describe_things(things) -> "座位（左边·近）、先祖（前面·远）"`，空列表返回空串。

**大脑**
- `body.status`：在"画面里：…"之后加"画面里的东西：座位（左边·近）、先祖（前面·远）"；没有物品、或 env 没有 `objects`（整图 OCR）时不加
- 眼睛的位置说明（`brain/images.py` 的 `scene_note`）：人之后列出物品"- 座位：(420, 610) 附近"，末尾加"没列出的东西按你自己看到的说"（有物品时才加）
- 提示词「光遇常识」加一句：状态里的"画面里的东西"是认出来的座位、篝火、乐器、先祖；想过去可以用 move 小步走、边走边看；坐下、弹琴还不会，别答应

**识别可视化网页**：物品框颜色同预览（座位蓝、篝火橙、乐器粉、先祖白）、图例加上；右栏"附近的东西"（`describe_env` 里，env 有 `objects` 时）

**不做**：物品单独的事件（眼睛的新鲜事已经会说）；走过去 / 坐下

## §4 上线门槛和测试

**v5 替换 v4 的门槛**（用户在 GPU 机器上做，步骤写进训练进度文档）
1. 认人不退步：同一批录像 v4、v5 各跑一次 `perception compare`，好友认出率、远处认出率不低于 v4；花地图上陌生人误报应减少
2. 物品：训练输出里每类验证集 mAP50 ≥ 0.6，不到的那类先补数据
3. `view --model models/sky-yolo-v5.pt` 真机看一圈：框得出、没有明显误认

`perception compare` 报告加一节「物品」：每类出现在多少帧、平均每帧几个（只统计，不和 OCR 比）。

**单元测试**
- 类别表：新类别在末尾、旧编号不变；只有 6 类的检测器下 `objects()` 为空
- 物品模式：人物行原样保留、物品行整体替换、"P2 是先祖"改行、写回前备份、缓存和标人分开、清单排序、没模型时没有候选
- `objects()`：`hits` 不够不算、过时 / 暂停返回空、按底边分远近、排序
- 状态有"画面里的东西"、整图 OCR 没有；`scene_note` 列物品；网页框 / 右栏 / 图例有物品；提示词有新句
- `compare` 物品统计
