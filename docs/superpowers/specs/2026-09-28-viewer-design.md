# 识别可视化网页 — 设计

日期：2026-09-28　状态：**待确认，未实现**

## 目标

把"团子看到了什么、认出了什么"实时画出来：游戏画面上用框标出认出的好友名字、陌生人、互动圆圈、聊天面板、新消息等，
旁边列出当前状态。用来：
- 调识别：一眼看出漏认、认错、框偏了
- 跑 `run` 时旁观：知道身体现在认为身边有谁、为什么叫醒了大脑
- YOLO 的 M2 离线对比：回放录像，看两套识别器各自框出了什么（见感知层设计 v0.2 §9、§10）

## 需求（已和用户确认）

1. **方案 A：本机网页**。程序起一个只给本机访问的网页，浏览器里显示画面 + 识别框 + 状态栏。
2. **两个入口**：
   - `run --view`：跑 Agent / 大脑时顺便打开可视化
   - 单独的 `view` 命令：只看不动，不往游戏里发任何输入
3. 显示哪些内容：见 §2、§3 的提案，**待确认**。

## 方案选择

**本机网页，画面和框放在同一份快照里发给浏览器，框和中文标签由浏览器画。**

放弃的方案：
- **B. OpenCV 窗口（`cv2.imshow`）**：项目装的是 `opencv-python-headless`，没有窗口功能；换完整版可能和别的包冲突；
  OpenCV 画不了中文，框上的名字会变成问号。
- **C. 盖在 MuMu 上的透明置顶窗口**：效果最像"框贴在游戏上"，但要处理 Windows 窗口 API、MuMu 窗口位置 / 缩放、点击穿透，
  工作量大、容易出兼容问题。以后真想要，可以在 A 的数据接口上再做。

## 1. 页面布局

```
┌──────────────────────────────────────────────┬──────────────┐
│ [暂停] [隐藏框]                  9.8 帧/秒 · 1920×1080 │ 团子看到的    │
│ ┌──────────────────────────────────────────┐ │ 识别：整图 OCR │
│ │                                          │ │ 身边的好友：… │
│ │     游戏画面 + 识别框（带中文标签）          │ │ 陌生人：…     │
│ │                                          │ │ 互动请求：…   │
│ └──────────────────────────────────────────┘ │ 最近事件：…   │
│                                              │ 图例          │
└──────────────────────────────────────────────┴──────────────┘
```

- 深色背景；窄屏（手机 / 平板）时状态栏排到画面下面
- **暂停**：停在当前这一帧，方便看清；**隐藏框**：只看原画面对比
- 右上角显示实际帧率和原图分辨率；程序停了显示"连不上"

## 3. 右侧状态栏（提案）

| 项 | 内容 |
|---|---|
| 来源 | 实时截图 / 回放的文件名 |
| 识别 | 整图 OCR（每几秒一次）/ YOLO 感知层 |
| 身边的好友 | `nearby()` 的结果 |
| 陌生人 | N 个（其中 M 个没点火）—— 只有 YOLO 有 |
| 互动请求 | 谁：什么 |
| 检测耗时 | 最近 30 帧的平均（YOLO 检测 / 整帧）—— 只有 YOLO 有 |
| 模式 | dry-run / LIVE（`run --view` 时） |
| 牵着手 | 谁 / 没有（`run --brain --view` 时，身体的推测） |
| 最近事件 | 最近 6 条事件（来了、走了、请求、陌生人……）（`run --brain --view` 时） |
| 待回复 / 刚说过 | 普通 Agent：攒着没回的消息数、最近说的 3 句（`run --view` 时） |

## 4. 两个入口

### `run --view`
- 和平时的 `run` 完全一样，只是身体 / Agent 每圈把"这一帧 + 认出的东西"交给可视化，行为不变
- 启动时打印网页地址并自动打开浏览器；退出时关掉网页服务

### `view`（只看不动）
- 实时截图 → 读聊天记录面板 + 认人（整图 OCR，或 YOLO）→ 网页上画框
- **不发任何输入**：不自动重开聊天面板、不接互动请求、不说话。玩家自己玩，旁边开着网页看
- 参数：
  - `--images <目录或图片>`：回放录像（比如 `record` 录的），不用连模拟器 —— 调识别、做 M2 对比用
  - `--model <模型>`：临时用这个 YOLO 模型（等于这次打开 `[perception]`）
  - `--port <端口>`、`--no-browser`
- 回放时识别同步做（不在后台线程），每张图都认完再显示，结果稳定可复现

## 5. 实现方式

- **只用标准库**起 HTTP 服务（`http.server.ThreadingHTTPServer`），不加依赖
- **接口**：`/` 页面；`/snapshot?after=<序号>` 长轮询 —— 有比这个新的一帧就返回 JSON（图 base64 + 框 + 状态），没有就等最多 2 秒
  - 图、框、状态在**同一份快照**里，框不会和画面错位。放弃"MJPEG 视频流 + 单独取框"的做法，因为两条通道各走各的，框会对不上
- **框的坐标用原图像素**，浏览器按显示大小缩放；中文标签由浏览器画
- **性能**：
  - 身体 / Agent 每圈调 `update()` 只记下这一帧的引用和框，限 `viewer.fps`（默认 10）次 / 秒，几乎不花时间
  - **有浏览器在看时才压 JPEG**；同一帧多个浏览器共用一次压缩结果；图缩到 1280 宽、质量 70
  - 身体主循环约 0.15 s 一圈，所以 `run --view` 实际约 6~7 帧 / 秒；要更流畅得等 YOLO 的 `capture = "own"`
- **要改的地方**：
  - `vision/viewer.py`（新）：网页服务 + 页面
  - `EnvWatcher` / `PerceptionWatcher` 各加一个 `overlay(now)`，返回"要画哪些框"；YOLO 这边顺便把圆圈认出的图标、人物关联到的名字记在轨迹上
  - `EventQueue` 加一个最近 20 条的历史（现在事件被大脑取走就没了）
  - `Body`、`Agent` 加可选的 `viewer` 参数，每圈调一次
  - `config.py` 新增 `[viewer]`：`host`、`port`、`fps`、`width`、`quality`
  - `cli.py`：`run --view`、`view` 命令

## 6. 安全和隐私

- **只监听 127.0.0.1**：画面里有好友昵称和聊天内容，默认只有本机能看
- 想在手机上看，要把 `viewer.host` 改成 `0.0.0.0`：同一局域网的人都能看，文档里写明这个风险，不做成默认
- 网页不存盘（和 `runs/<…>/frames/` 不同）；要留证据用 `shot` 或 `record`

## 7. 边界情况

- 截图失败：保留上一帧，不刷新
- 程序退出 / 崩了：页面显示"连不上（程序停了？）"，程序重启后自动接上
- 端口被占用：启动时报错，提示用 `--port` 换一个
- 画面整屏黑（切场景）：照常显示，状态栏标"画面黑着"
- 回放的图分辨率不是 1920×1080：框按原图坐标画，照样对得上；识别本身的坐标标定是按 1920×1080 的，可能不准

## 8. 测试

- `overlay()`：OCR / YOLO 两种识别器给出的框和标签（合成数据）
- 网页服务：开在随机端口，取 `/` 和 `/snapshot`；没有新帧时返回 204；限帧率；同一帧只压缩一次
- `Body` / `Agent`：带 `viewer` 时每圈调用、出错不影响主循环
- `view --images`：回放两张合成图，快照里有框
