# ③ 分清好友在跟谁说话

日期：2026-10-05。路线图 `2026-10-04-future-roadmap-design.md` 的第一项（A 组：陪好友更像个人）。
下面「已定」是 10-05 和用户逐条问定的。

## 1. 起因和目标

现在每句好友聊天都立刻叫醒大脑，大脑基本句句接。`brain/reflex.py` 的 `addressed()` 有一套从严的规则，但只用来决定冒不冒输入气泡、做不做小动作；
大脑提示词里只有一句「明显不是跟你说的，不用回」。

真机例子：
- 10-04 21:31~21:40（`runs/20261004-212739-live-brain`）：番茄和卡洛当着团子聊，团子连着回「啥好了呀」「我怎么了呀」「你到底在说啥呢」；番茄专门说了一句「你先不用回复哦 团子」
- 10-03 21:08（`runs/20261003-210211-live-brain`，三个好友）：好友之间用第三人称说团子（「这孩子不认地图」「他乱说的」「他现在还没眼睛呢」），团子每句都接

**目标**：好友之间聊天时团子默认不接；叫到它、接它的话、说给大家的才接；觉得有意思偶尔插一句，算进主动开口的额度。

## 2. 已定

| 问题 | 定了什么 |
|---|---|
| 不是跟团子说的话 | 默认不接、偶尔插一句，插话算主动开口的额度（路线图） |
| 「跟别人说」要不要叫醒大脑 | 插话额度还有就照样叫醒（事件里标好）；额度用完放成背景事件，下次醒来一起看 |
| 团子开口算接话还是插话 | 按叫醒那一轮的事件算：有一句是 跟你说 / 说给大家 / 拿不准 就是接话；整批都是跟别人说才是插话。拿不准的交给大脑判断，它接了就算接话 |
| 第三人称说团子 | 带团子名字的（「团子不认地图」）算跟你说，和现在一样；不带名字的（「这孩子」「他乱说的」）进拿不准 |
| 判断怎么做 | 纯规则 + 一点对话状态，不调模型（另外两种：规则判不了的再问 Haiku，或者全部交给模型判，都更慢、更费额度，拿不准的话大脑本来就会再看一遍） |
| 好友的叫法 | friends.md 每节加一行约定格式 `- 叫法：卡洛、老登`，程序只读这一行，再加上游戏昵称 |
| 离线标注 | 命令导出 → Claude 初标 → 和规则对一遍 → 只把不一致的加上随机抽的一部分给用户核对；不做管理面板页面 |
| 门槛 | 见 §8 |

卡洛的 `#` 命令照旧单独处理，不进这套判断。陌生人的聊天留给 ⑤，这一期一律算拿不准（和现在一样交给大脑）。

## 3. 判断模块 `brain/addressee.py`（纯计算）

**输入**：一句话（说话人、内容、时间，用身体的钟），以及身体交进来的：团子最近说话的时间、身边的好友（`env.nearby`）、好友名单和各自的叫法。
模块自己记最近 2 分钟的聊天和每句的判断。

**输出**：`Verdict(label, reason, target)`
- `label`：`me` 跟你说 / `other` 跟别人说 / `all` 说给大家 / `unsure` 拿不准
- `reason`：一句人话（「叫了小明」「在接你的话」「和小明一来一回」），进事件和日志
- `target`：`other` 时在跟谁说（好友名单里的名字），其余为空

**规则**（从上往下，命中第一条就停）：

0. 看不出是谁、或者不是好友（`is_friend_fn`，容忍 OCR 错字）→ `unsure`「不是好友说的」
1. 叫了团子（`[proactive] self_names` 在句子里，第三人称也算）→ `me`「叫了你」
2. 叫了别的好友（昵称或叫法，不算他自己）→ `other`，target = 那个人，「叫了X」
3. 句子里有 `group_words`（大家、你们、各位），或者身边有两个以上好友时开头是 `greet_words`（晚上好、来了、拜拜……）→ `all`
4. **接你的话**：团子 `followup_window`（30 秒）内说过话，这是他在那之后说的头 `followup_lines`（2）句，并且团子说完之后没有跟他有关的 `other`（他跟别人说、或别人跟他说）→ `me`「在接你的话」
5. **还在跟别人说**：`thread_window`（20 秒）内满足其一，并且这之后团子没开口：
   - 他上一句是 `other`、target = X →「还在跟X说」
   - X 上一句是 `other`、target = 他 →「在回X」
   - 他和 X 交替说话（A、B、A、B 至少三句），中间没有团子 →「和X一来一回」

   → `other`，target = X
6. 身边只有他一个好友，`thread_window` 内也没有别的好友说过话 → `me`「身边只有他」
7. 其余 → `unsure`

**叫法**（`addressee.aliases(friends_md, names)`）：friends.md 里 `## 昵称` 那一节中以 `- 叫法：` 开头的一行，按顿号、逗号、空格分开；加上昵称本身。
匹配：昵称或叫法在句子里出现（叫法 ≥ 3 个字时允许错一个字，1~2 个字的叫法只认原样（2 个字错一个就只剩一个字对得上，「卡住」会算叫了「卡洛」））。friends.md 每次判断前重新取（和现在一样跟着身体的好友名单走，改了不用重启）。
`memory init` 的好友模板多一行 `- 叫法：`；已有的 friends.md 由用户自己加，没加的好友只认昵称。

**已知弱点**（交给 §8 的评估去量，不预先补）：
- 「好了？」「🌚🌚🌚」这种短句如果落在团子说完的 30 秒内，会被规则 4 判成跟你说。旧日志里团子句句都接，「接你的话」的窗口几乎一直开着，所以旧数据上会显得偏差大；团子不乱接之后会好一些
- 好友可能在跟画面外的人、陌生人（读不到）或语音里的人说话，这种话看着没头没尾，只能落进拿不准
- **规则 4 会自己续命**（最终评审发现，没改代码）：团子说过话后，每个好友接下来头 2 句没点名的话都判 `me` → 大脑回 → 窗口重新打开；而 `occasion.reply_state` 把团子之后任何好友的话都算「有人接」，所以「插完没人理就别再插」「连着 3 句没人接」这两道护栏永远不触发。
  真机验收时数一数「在接你的话」→ 团子回 → 又「在接你的话」这种连锁；要收紧时可选：插话那一轮之后不开规则 4 窗口 / 规则 4 只给团子上一句回应的那个人 / `reply_state` 跳过判成 `other` 的句子

## 4. 身体和大脑怎么接上

**身体收到一句聊天**（`Body._heard`）：
- 每句判一次，`Verdict` 挂在这一句上（`Message` 不改，身体按顺序存一份），后面所有地方共用这一个判断
- 日志（INFO）一行：`跟谁说：阿花「好了？」→ 跟别人说（在回小明）· 身边 [小明, 阿花]`；以后的运行能拿它原样回放（§8）
- 给大脑的事件：
  - `me` / `all` / `unsure` → `chat` 事件（照旧立刻叫醒），正文末尾带标注：`聊天  阿花：「你呀」（跟你说：在接你的话）`
  - `other` → 插话额度还有（`occasion().left > 0`）放 `aside` 事件（不在 `BACKGROUND` 里，叫醒）；额度用完放 `aside_bg`（在 `BACKGROUND` 里，攒着）。正文：`聊天  阿花：「好了？」（跟别人说：在回小明）`
  - 冷场结束时附的「你刚才在想」照旧跟在正文后面
- 身体里原来看 `events.has("chat")` 的地方（聊天面板别因为安静关掉、注意力别转走）把 `aside` / `aside_bg` 也算进去：好友在聊天，面板照旧开着

**接话还是插话**：
- `Brain.chat_turn` 只看 `chat` 和 `owner_command`，**不看 `aside` / `aside_bg`**。所以整批都是跟别人说的那一轮，`say` 就是主动开口，走现有的护栏（额度、`min_gap`、连着没人接就停、身边没好友不说），被拦时的原因照旧
- `Body._pending_reply`（有没接的好友聊天时说话算接话）只看 `me` / `all` / `unsure` 的句子
- `[proactive] enabled = false` 时没有插话：`other` 一律放 `aside_bg`，提示词写不接（§5）

**反射、账本改用同一个判断**：
- 冒输入气泡、被叫到时的小动作只看 `me`；`reflex.py` 的 `addressed()` 挪进 `addressee.py`（`legacy_addressed`，只在 `enabled = false` 时用）
- 关系卡「跟团子说的几句」（`ledger.heard` 的 `to_me`）、`_cheered_at` 只算 `me`
- 冷场追踪（`LullTracker.heard`）不变：谁说话都算有人说话

**status**：「场合」那一行后面加对话走向：最近 60 秒（`thread_window × 3`）里有两个好友互相判成 `other` 时写「阿花 和 小明 在聊（1 分钟内 6 句）」，没有就不写。

**聊天记录**（真机 / 沙盒共用的 `brain/transcript.py`）：聊天行带上标注（沙盒的 `heard` 行改由身体经 `body.on_line` 写，`sandbox/control.py` 的 `_say` 不再自己写，这样两边都带标注），管理面板 `chatlog.js` 在行尾用小字显示（跟你说 / 跟别人说 → X / 说给大家 / 拿不准）。

## 5. 大脑的规矩（提示词）

`brain/prompt.py`「说话」一节「乱码、纯表情、刷屏、明显不是跟你说的，不用回」拆开：乱码、纯表情、刷屏照旧不回；「不是跟你说的」换成（`[addressee] enabled` 时）：

```
- 身体会在每句聊天后面标出它在跟谁说：
  - 跟你说：照常接。
  - 说给大家：你也是其中一员，想接就接，像朋友间搭腔，不用每句都回。
  - 跟别人说：默认不接，让他们聊。真有想法（接梗、吐槽、他们在说你）可以插一句，算主动开口，被身体拦下就别说；插完没人理就别再插。
  - 拿不准：自己看前后几句判断。觉得是在跟别人说，就按跟别人说处理；拿不准时宁可不接。
- 有人让你先别回、别插嘴，照做，直到又有人叫你。
- 不接的时候在心里写一句“不说：他们在聊…”。
```

`[proactive] enabled = false` 时「跟别人说」那条换成「跟别人说：不接」，不提插话。
「主动开口」一节「热闹：……插一句吐槽……」后面补「好友之间在聊的，插话的规矩看『说话』一节」。
DeepSeek 备用大脑用同一份提示词；`FALLBACK_NOTE` 加一行「标着『跟别人说』的话默认不接」（10-03 晚它的说听比 0.9~1.15，比 Claude 更爱接）。

`enabled = false`：提示词逐字是原来的。

## 6. 配置（`[addressee]`）

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉逐字照旧：不判、事件不带标注、没有 `aside`、提示词是原来那句、反射用原来的 `addressed()` 规则（搬进 `addressee.py` 保留成 `legacy_addressed`） |
| `followup_window` | 30.0 | 从 `[reflex]` 挪来；`[reflex] followup_window` 读到时警告、照样生效（`[addressee]` 里没写时用它） |
| `followup_lines` | 2 | |
| `thread_window` | 20.0 | |
| `group_words` | 大家、你们、各位 | |
| `greet_words` | 晚上好、早上好、中午好、来了、我来啦、拜拜、晚安、走了 | 身边两个以上好友时算说给大家 |

管理面板设置页加 `addressee.enabled`。沙盒照样生效（沙盒的身边就是名单）。

**出错**：判断抛异常 → 记日志、这句按 `unsure`（交给大脑，和现在差不多）。friends.md 读不了 → 没有好友名单，全部 `unsure`。

## 7. 不做

- 不调模型判断（规则判不了的交给大脑）
- 陌生人的聊天怎么判（⑤）
- 从语气、标点猜对象（「你呀」到底在说谁），短句留给大脑
- 学好友的说话习惯来调规则

## 8. 验证

**单元测试**（`python -m pytest -q`，占位人名）：
- 每条规则正反各一例；叫法解析（顿号 / 逗号、1~2 个字的叫法只认原样）
- 10-04 那段改成占位名的回放：A、B 互相说「好了」「你呀」「哎呀」，团子没开口时判成 `other`
- 事件分成 `chat` / `aside` / `aside_bg`；额度用完时 `other` 进 `aside_bg`
- 整批都是 `aside` 的那一轮 `say` 走主动开口的护栏、额度用完被拦；有一句 `unsure` 时不拦
- 反射只对 `me` 冒气泡；`enabled = false` 时提示词、事件正文逐字不变

**离线评估**：
- `python -m skydango addressee label <runs…> [--out datasets/addressee/<时间>]`：
  - 从各次运行的 `agent.log` 取聊天（「读到」「已发送」；有「跟谁说」行就用它记的身边，旧日志没有就用 5 分钟内说过话的好友估，`agent.log` 里没有逐条的来去记录）
  - 挑出多人聊天段落（3 分钟内有两个以上好友说话）+ 约 20% 单人聊天当对照，写 `lines.jsonl`
  - Claude 初标（sonnet、一次性 `claude -p`、令牌同大脑、分批、缓存、额度用完可续跑，不复用 `assist.Reviewer`（它绑死了图片帧）：文字标注单写一个小的分批 + jsonl 缓存，额度用完的处理照 `perception attrs-label`）：跟团子 / 跟别人 / 大家 / 看不出
  - 规则按时间顺序重放一遍；写 `review.md`：两边不一致的全列、一致的随机抽 20%，每句带前后 6 句上下文和两边的判断，用户在 `标：` 后填 跟团子 / 跟别人 / 大家 / 看不出
- `python -m skydango addressee eval <目录>`：读回 `review.md`，没核对的句子用两边一致的那个标签，`看不出` 的不计；出 `report.md`（混淆矩阵 + 每条判错的句子和上下文），三条门槛：
  1. 标准答案是「跟别人」的句子，规则判成 `me` 的 ≤ 5%（团子插嘴，最要紧）
  2. 标准答案是「跟团子」的句子，规则判成 `other` 的 ≤ 10%（判成 `unsure` 不算错，交给大脑）
  3. 规则判 `unsure` 的 ≤ 全部的 40%（超过说明规则基本没起作用）
- 数据：10-03 21:02（三个好友，201 句）、10-03 23:04、23:25、10-04 21:27（111 句）这几次有多人聊天
- `datasets/addressee/` 不进 git（好友原话）

**沙盒**：新剧本 `docs/sandbox-scenarios/两个好友互相聊.toml`（占位名 `小明` / `阿花`，README 表格加一行）：两人互相叫名字聊 8 句 → 团子大部分不接、插话不超过额度；之后「团子你说呢」→ 立刻接。

**做成**：离线三条门槛过线 + 沙盒剧本符合预期 → 合并上线。旧日志（没有「跟谁说」记录）上算出的门槛只作参考：团子当时句句都接，「在接你的话」的窗口几乎一直开着（4 次旧运行里 325 句挑出的句子有 266 句是这条规则判的 `me`），`report.md` 按规则理由分开列了混淆矩阵；正式门槛用合并之后录下的新日志（带「跟谁说」行）。代码带着 `enabled` 默认开合并，不合适可在管理面板设置页关掉。
**真机**（最终验收）：有两个以上好友在的一晚，抽查 `agent.log` 的「跟谁说」行；数一下只有 `aside` 的那几轮团子开了几次口；数「在接你的话」→ 团子回 → 又「在接你的话」的连锁（见 §3 已知弱点）；问好友有没有觉得「怎么什么都接」。结果记进路线图的「已定」。
