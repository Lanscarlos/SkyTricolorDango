## 0. 测试命令 `#spin` / `camera spin`

设计已写好，见主人命令设计 `2026-09-27-owner-commands-design.md` §6（普通模式 `#spin`，命令行 `camera spin`）。

**用这个命令在真机回答总纲 §14.5 的问题**，结果写进 `docs/game-ops.md` §2 的方向键那一行：
一圈多少秒、是否匀速、聊天面板开着能不能转、画面多模糊、水平视野角多少度、靠墙时镜头的表现。
§1 的参数（`seconds_per_turn`、`hfov`）用这里的实测值。

**实现备注（代码部分）**：
- 纯计算在 `vision/sweep.py`（方位角、8 方位、合并、`find_self`、远近分档），`PerceptionWatcher.sweep()` 跑检测 / OCR 喂给它
- 牵着手转圈时，对方每帧都在画面中间：几乎不动的链上的名字标签单独记成"身边"，不按方位合并（否则会被摊到 8 个方向）
- 名字标签读不出 / 不在好友名单里的人，扫描结果里记成"没认出名字的人"，不算陌生人
- 转圈画面糊，好友的标签某几帧没检测到 / 没读出来：和好友方位相差 < `merge_deg` 的"陌生人 / 没认出名字的人"算同一个好友（黑影不算）
- 模型在团子身上同时出 `self` 和 `player` 框时，`player` 那个不算另一个人；认出的团子框四周放宽 25% 排除，和 `self_roi` 同时生效；转镜头（`camera` / `camera_reset`）后作废
- 转圈中某张截图失败只跳过那张，照样转满一圈（半路停下镜头朝向就乱了）
- 暂停恢复时清掉每条轨迹的框高历史，暂停前后的框高不拼在一起判"走过来"
- 陌生人走过来的冷却按"陌生人"整体算；身份还没判定的人（没到 `stranger_after`）不判走过来
- `look [图片]` 可以直接描述一张截图，并先打印交给眼睛的位置说明（§2 验收用）

## 1. 环绕扫描 + 转圈认团子

想法、取舍和注意事项见总纲 §14，这里只写实现层面的约定。

### 1.1 转和截

复用 §0 的 `Camera.spin()`（转一圈、按 fps 截图、每张带"按住后第几秒"）。转的全程包在 `env.held("camera")` 里（一期 §4），
截下的帧交给感知层单独处理，不走平时的 `observe()`。

### 1.2 汇总：`PerceptionWatcher.sweep(frames) -> SweepResult`

- 输入：`[(t, frame), ...]`，`t` 是按住后第几秒
- 每帧跑检测 + 本帧内的名字 OCR / 圆圈匹配（不更新平时的追踪器和 `last_seen`，扫描是一次独立的观察）
- 每个检测的**方位角** = `t / seconds_per_turn × 360° + (框中心 x − 画面宽/2) / 画面宽 × hfov`，取模 360；
  0° = 开始转之前的正前方，顺时针为正（向右转）
- **同一个人合并**：好友按名字合并；陌生人 / 黑影按方位聚类（相差 < `merge_deg` = 30° 算同一个），每个聚类取出现帧数最多的类别
- 方位折成 8 个方向：前、右前、右、右后、后、左后、左、左前（每个 45°）
- 结果：

```python
@dataclass
class SweepEntry:
    direction: str          # "右后"
    degrees: float
    who: str                # 好友名 / "陌生人" / "陌生人（没点火）"
    frames: int             # 在多少帧里出现
    distance: str | None    # 近 / 中 / 远（§4 的算法；§4 没做完时为 None）

@dataclass
class SweepResult:
    entries: list[SweepEntry]
    self_box: Rect | None   # 转圈认出的团子（见 1.3）
    frames: int
    seconds: float
    def text(self) -> str:  # "正前方：懒洋洋大王；右后方：2 个陌生人（1 个没点火）"
```

### 1.3 转圈认团子

在 `sweep()` 里一起做：
- 候选：所有 `player` / `self` 框（第一版模型的 `self` 可能不准，一起算）
- 按位置把各帧的框串起来（IoU ≥ 0.3），算每条链：出现帧占比、框中心移动量（相对画面宽，取各帧到均值的平均距离）、离画面中心的距离
- 选：出现帧 ≥ 80%、移动量 < `self_motion`（默认 0.03）、离中心最近的那一条 → 取各帧框的中位数作为 `self_box`
- 有两条都满足且框中心相距 < 团子框宽（牵手时对方紧挨团子）→ 不下结论，`self_box = None`
- 用处：
  1. **运行时**：`self_box` 不为空时更新 `PerceptionWatcher` 的团子位置（替代固定的 `self_roi`，下次转圈前一直用它）
  2. **标注**：`perception label --spin <spin 录像目录>` 用 `sweep()` 认出的团子给每帧补 `self` 框

### 1.4 接给大脑

- 打开感知层时，`look_around` 改成：`Camera.spin()` → `sweep()` → 返回 `SweepResult.text()`（纯文字，不叫眼睛）；关着时仍用现在的眼睛 4 张图
- 大脑工具的名字、说明、参数都不变；说明里加一句"几秒就好"（现在写的是"要十几秒，别常用"，打开感知层时换掉）
- `#spin` 在打开感知层时，回复后面加 `SweepResult.text()`（主人命令设计 §6 已预留）
- 只在大脑调 `look_around`、主人发 `#spin` 时转；**身体不自动转**（刚到新地方要不要自动转，等二期用过一段时间再说）

### 1.5 配置

`[spin]`（§0 新增的）加：`hfov = 90.0`（**待 §0 标定**）、`merge_deg = 30.0`、`self_motion = 0.03`。

### 1.6 测试

- 方位角换算：给定 t、框位置、`seconds_per_turn`、`hfov`，算对方向和 8 方位
- 合并：同名好友多帧合一；两个陌生人方位差 > 30° 不合并
- 认团子：合成"中间不动 + 其他横扫"的框序列 → 认出中间那个；牵手（两个都不动且紧挨）→ None
- `look_around`：打开感知层时走 sweep、不叫眼睛；关着时走眼睛（用假 camera / 假 env）

## 2. 检测结果交给眼睛

### 问题

眼睛（Haiku）现在只拿到"名字位置"（`label_note`，OCR 认出的好友名字标签在图里的位置），陌生人、黑影、团子都要它自己看，
容易把陌生人说成某个好友、或者编名字。

### 方案

新增 `scene_note(env, now, scale) -> str`（`brain/images.py`，和 `label_note` 放一起），用 `env.overlay(now)`（可视化网页已经在用的接口）拼出：

```
画面里认出的人（坐标按这张图）：
- 懒洋洋大王：(812, 340) 附近
- 陌生人（没点火，黑影）：(1105, 420) 附近
- 陌生人：(300, 390) 附近
- 团子（就是"你"自己）：(640, 470) 附近
没列出的人都叫"陌生人"。
```

- 替换现在 `Eyes.describe_frame` 和 `Body.look` 里的 `label_note`；`env` 没有 `overlay`（旧识别器）时退回 `label_note`
- 眼睛的系统提示词 `EYES_SYSTEM` 改一句："人名只用给出的名字；给出的陌生人、团子位置照用；没列出的人都叫'陌生人'"
- `LOOK_REQUEST` 的"好友"一项加："团子自己不用描述"

### 测试 / 验收

- 单元测试：`scene_note` 的格式、坐标缩放、各类别文字
- 验收：用 `python -m skydango look` 对 20 张不同场景的截图各跑一次，眼睛描述里**编出来的名字 0 次**、把陌生人说成好友 0 次（人工核对，结果记进本文 §6）

## 3. 认说话人：头顶"正在输入"气泡

### 问题

聊天记录面板里，好友的消息带名字，但**陌生人的消息只显示"陌生人"**（game-ops §3），不知道是画面上哪个人说的；
大脑想回应、做动作也不知道对着谁。

### 依据

游戏里有人在打字时头顶会出气泡，先是 `..`，发出后显示文字几秒（game-ops §3："头顶气泡显示有延迟：先显示'正在输入'的 `..`，几秒后才出文字"）。
之前放弃头顶气泡，是因为从气泡里**读字**不可靠；这里只检测"头顶有没有气泡"，是很容易的检测任务。

### 方案

- 新 YOLO 类别 `typing`（头顶的聊天气泡，不管里面是 `..` 还是文字），**追加在类别表末尾**（总纲 §4）；
  补数据时录"好友 / 陌生人在打字、刚发出消息"的画面
- 关联：气泡框在哪个人物框（或名字标签）正上方，就记到那条轨迹上：`track.data["typing_at"] = now`
- 身体读到新消息时（`Body._heard` / `Agent.step`）：
  - 说话人是好友（有名字）→ 不需要，已经知道是谁
  - 说话人是"陌生人"或读不出 → 找最近 `typing_window`（默认 8 s）内头顶出过气泡、且**不是好友**的人物；
    **恰好一个** → 消息后面加注"（说话的可能是右前方那个没点火的陌生人）"，方向按画面位置粗分（左 / 中 / 右 × 远 / 近）；
    零个或多个 → 不加注
- 团子自己的气泡（输入框开着时团子头顶也有气泡，game-ops §3）：气泡在团子框上方的排除
- 可视化网页加一种框：`typing`

### 要在真机确认的

- 别人（尤其是陌生人、没解锁聊天的陌生人）打字时，自己这边看得到气泡吗
- 气泡从出现到消息出现在聊天记录面板里，前后差多久（决定 `typing_window`）
- 气泡会不会被名字标签、圆圈挡住

### 测试

- 气泡关联到正下方的人物；团子头顶的气泡被排除
- 恰好一个候选 → 加注；零个 / 多个 → 不加注；好友消息不加注
- `typing_window` 过期不算

## 4. 距离和走向

### 方案

- **距离**：人物框高 ÷ 团子框高（§1.3 的 `self_box`，或模型的 `self` 框）。用团子做参照可以抵消镜头拉近拉远；
  没有团子框时退回"框高 ÷ 画面高"。分三档：近（比值 ≥ 0.8）/ 中（0.4~0.8）/ 远（< 0.4），**阈值待真机标定**
- **走过来**：同一条轨迹最近 1.5 s 内框高增大 ≥ 25%，且框中心在往画面中间移动（或一直在中间）→ 判定"朝团子走过来"
- 新事件 `approach`："卡洛朝你走过来了" / "有个陌生人朝你走过来了"
  - 每个人 60 s 内最多报一次；牵着手的那个人不报；暂停（一期 §4）期间不判
  - 眼睛**不**因为 `approach` 自动看（`AUTO_LOOK_KINDS` 不加），省额度
- `status` 加一项"离你最近的：懒洋洋大王（近）"
- `SweepEntry.distance` 用同样的算法（§1.2）

### 测试

- 距离分档（有 / 没有团子框两种）
- 框高持续增大 + 往中间移 → 一次 `approach`；60 s 内不重复；牵手对象不报；暂停期间不判
- 框高抖动（±10%）不触发

## 6. 二期验收

| 项 | 目标 |

| 环绕扫描 | 5 个场景各扫一次，人工对照录像：好友方向对 ≥ 90%（8 方位，允许差一格）；一次扫描从调用到返回 ≤ 5 s |

## 7. 待确认（2026-09-28 用户已确认）

1. 认说话人：**只在恰好一个候选时加注**，零个 / 多个都不加（不把不确定的猜测交给大脑）
2. `approach` 事件**也报陌生人**（"有个陌生人朝你走过来了"），另加开关 `[perception] approach_strangers = true`，陌生人多的地方嫌吵可以关掉；
   陌生人没有身份，冷却按"陌生人"整体算（60 s 内最多报一次）
