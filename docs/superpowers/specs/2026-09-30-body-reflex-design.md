# 身体反射 — 设计

日期：2026-09-30　状态：**设计已和用户确认，待写实施计划**

## 背景：让团子"活着"

远期目标（用户）：团子像 Neuro-sama 那样有"活着"的感觉（游戏里的伙伴，不做主播）。和用户对过，现在最不像活的是：

- A 站着像木头人：有人说话不看、来了人没反应
- B 说话没性格、太乖
- C 没有情绪起伏
- D 不记得人、接不上以前的梗
- E 反应慢半拍

拆成四个子项目，按顺序各走一遍 设计 → spec → 计划 → 实现：

1. **身体反射**（A + E，这份）
2. **关系账**（D）：按人记见面、经历、梗、熟悉度
3. **情绪**（C）：心情和"对谁有点小情绪"，记在关系账上，影响反射和语气
4. **性格语气**（B）：放开太乖的规则，口头禅、坏习惯、梗的来源

前一步"看场合主动开口"（`2026-09-29-proactive-chat-design.md`）还没在真机跑过；这份的实现可以先做，真机验证时一起跑。

## 为什么要反射

大脑一轮要几秒到十几秒（事件攒 `chat.debounce` 0.8 秒 → Sonnet 想 → 调工具），好友说完话看到的是一段空白。
身体主循环一秒好几圈：常见时刻由身体按规则当场反应，大脑再补上说什么。好友看到的是"马上有反应，然后回话"。

分工（用户选了方案三：混合）：

| 时刻 | 谁 | 做什么 |
|---|---|---|
| 有人在跟团子说话 | 反射 | 马上打开输入框冒"正在输入"气泡（主）；偶尔先做个小动作再开框 |
| 别人对团子挥手 / 鞠躬 | 反射 | 用同一个动作回礼，按概率回。动作识别（`[gesture]`）还没有模型，代码先写好、有模型自动生效 |
| 闲着很久 | 反射 | 隔几分钟（随机）从"闲着的动作"清单里挑一个做 |
| 被夸 / 被逗、好友在弹琴 | 大脑 | 要读懂话、看懂画面，关键词做不好；提示词说明想用动作就先 `emote` 再 `say`，气泡已经在了不用急 |

不做（这一期）：转镜头看说话的人（`always` 模式下要关聊天面板几秒、说话人位置只有 YOLO 气泡能猜）；反射换轮盘；情绪、关系（后面的子项目）。

## §1 总览

- **新文件 `brain/reflex.py`**：纯决策、不碰设备（同 `occasion.py` / `peek.py`）。输入：新聊天、身边好友、团子上次说话的时间、轮盘上的动作、时间；输出：要不要开框、要不要做哪个动作
- **身体执行**（`brain/body.py`）：`step` 里问 reflex，自己去做
- **共同规矩**
  - 只用**轮盘上已有**的动作（`EmotePlayer.on_wheel()`），反射不换轮盘
  - 做完放一条**背景事件**告诉大脑（"你下意识回了个挥手"），不单独叫醒，免得它再做一遍
  - 这些时候不做：黑屏、`track` 在跑、有面板挡着（`clear_view` 不放行）、正在换轮盘、有互动请求等着接
  - dry-run 只写日志、不按键
  - 牵着手照常做（做动作不会松开牵手，用户实测，见 game-ops §4「副作用」）
  - `status` 和可视化网页的大脑时间线里看得到最近的反射（"刚才下意识：回了个挥手（12 秒前）"）
- **判断"在跟团子说话"**（`reflex.addressed()`，先从严，真机看频率再放宽）。聊天说话人是好友（和 occasion 同一个匹配），且满足任一条：
  1. 话里带 `[proactive] self_names`（默认"团子""三彩"）
  2. 团子上一句话之后 `followup_window`（30 秒）内
  3. 身边恰好一个好友，就是他在说

  团子自己的消息、主人 `#` 命令、陌生人都不算

## §2 输入气泡

普通 Agent 已经有 `sender.type_ahead`（`agent.py`，game-ops §3「发消息」真机验证过：输入框开着头顶一直有"正在输入"），大脑模式搬过来，但开框时机提前到身体读到消息的那一刻。

**开**：`step` 读到新聊天、`addressed()` 为真 →（先做 §3 的小动作）→ `panel.before_speak()` → `sender.open()`。
框已经开着（上一句还没想完）不重复开。dry-run 不开框，日志写"会冒输入气泡"。

**关**（只关团子自己开的：`sender.cancel()`，不查 adb）：
1. 大脑 `say`：直接用这个框发（`sender.send` 已经处理 `_opened`）
2. 大脑这一轮结束、没说话：关掉（像打了几个字又删了）。`BrainLoop.wake` 结束时通知身体
3. **任何按键 / 点屏幕的动作之前**：身体里 `emote`、`camera` / `camera_reset` / `look_around`、`move`、`track`、`check_friend` / `look_person` 换角度、`panel_press` / `panel_close`、互动接受、反射动作，统一先关框。
   各模块有的会自己查 `ime_shown()`（emotes、camera、panel、wheel、social），`move` 和 `track` 不查 —— 框开着按 W/A/S/D 会打字。在身体一层统一关，不漏
4. 有互动请求要接：`social` 看到输入框开着不点圆圈；牵手比气泡要紧，先关框让它接
5. 超时：开了 `bubble_max`（45 秒）还没说话就关（大脑一轮最长 120 秒）

**大脑**：提示词加一句"有人跟你说话时，身体已经替你冒了输入气泡；想好就 say，不想回也行，身体会关掉"；`status` 里"输入框：开着（身体替你开的）"。

**风险**：输入框开着时聊天面板上移约 75 px（game-ops §3「读消息」），普通 Agent 真机读得到，大脑模式没这么跑过；`addressed()` 太宽会让气泡冒了又消，所以先从严。

## §3 动作反射和额度

| 反射 | 触发 | 做什么 | 配置 |
|---|---|---|---|
| 被叫到 | §2 开框之前 | 按 `addressed_chance` 做 `addressed` 清单里的一个 | `addressed = []`、`addressed_chance = 0.3` |
| 回礼 | 感知层的 `pop_gestures()` | 按 `return_chance` 做 `return_map[标签]` | `return_map = {}`（键是 `[gesture] labels` 里的标签，如 `wave = "挥手"`）、`return_chance = 0.7` |
| 闲着 | 距上次"有动静"过了 `idle_min`~`idle_max` 之间的随机秒数 | 从 `idle` 清单挑一个，不和上一次重复 | `idle = []`、`idle_min = 180`、`idle_max = 420` |

- **清单默认空**（用户先空着，配置模板里写注释好的例子）；清单里的动作不在轮盘上就跳过；启动时一个都不在就在日志说一声
- **"有动静"**：有人说话、团子说话或做动作、大脑调了任何按键类工具、反射本身。闲着的计时从这些时刻重算
- **回礼和大脑**：回了 → 放背景事件"小明对你挥手，你回了个挥手"，原来的 `gesture` 事件不发；没回（没抽中 / 做不了） → 照旧发 `gesture` 事件，大脑决定
- **框开着时**：闲着不做（正在"打字"）；回礼照做：关框 → 回礼 → 再开框
- **额度**：反射和大脑互不抢
  - 反射**不占**大脑的动作冷却（`emotes.min_interval` 20 秒）：不然刚点完头，好友一夸，大脑想害羞被拦
  - 反射自己：`quota_window`（600 秒）里最多 `quota`（4）个
  - 任何两个动作（反射或大脑）之间至少 `min_gap`（4 秒），给动画留时间
  - 改动：`EmotePlayer.perform(name, reflex=True)` 不更新大脑冷却的计时，只更新"上一个动作的时间"（`min_gap` 用）；大脑的 `emote` 也要看 `min_gap`

## 配置（新 `[reflex]`，`config.py` 的 `ReflexConfig`）

| 键 | 默认 | 作用 |
|---|---|---|
| `enabled` | `true` | 总开关；`false` = 完全照旧（不开框、不做反射动作、gesture 照旧交给大脑、提示词不加那句） |
| `bubble` | `true` | 输入气泡单独开关 |
| `followup_window` | 30 | 团子说完多少秒内好友接话算"在跟团子说" |
| `bubble_max` | 45 | 替大脑开的框最长开多久 |
| `addressed` / `addressed_chance` | `[]` / 0.3 | 被叫到时的小动作 |
| `return_map` / `return_chance` | `{}` / 0.7 | 回礼 |
| `idle` / `idle_min` / `idle_max` | `[]` / 180 / 420 | 闲着的小动作 |
| `quota_window` / `quota` | 600 / 4 | 反射动作额度 |
| `min_gap` | 4 | 任何两个动作之间至少隔几秒 |

`config.example.toml` 加这一节（清单写注释好的例子）；管理面板设置清单（`console/settings.py`）加 `enabled`、`bubble`。**数字都是估的**。

## 测试（`python -m pytest -q`，假设备）

- `addressed()`：三条各测一次；团子自己、`#` 命令、陌生人、不沾边的好友闲聊都不算
- 开框：读到对团子说的话当圈就开；已开不重复；dry-run 不开
- 关框：`say` 用同一个框发；一轮结束没说话关；超时关；有互动请求关；只关自己开的
- 按键类工具（emote / camera / move / track / check_friend / 面板 / 互动接受）执行前都关了框
- 三种反射：概率（注入随机数）；动作不在轮盘上跳过；框开着时闲着不做、回礼关框再开；额度；`min_gap`；不占大脑冷却
- 回礼后是背景事件、`gesture` 不发；没回照旧发
- 闲着计时被"有动静"重置
- 总开关 `false`：不开框、不做动作、`gesture` 照旧、提示词不变

## 真机验证（单元测试过了不等于游戏里能用）

1. `run --view --live`，和好友聊一阵：气泡什么时候冒、会不会冒了又消、团子回话的那句是不是从这个框发出去的
2. 框开着时聊天面板读不读得到新消息（面板上移）
3. 框开着时来一个牵手请求：能不能接上
4. 给 `idle` / `addressed` 填上轮盘上的动作，看频率合不合适；反射之后大脑马上做动作有没有被拦

之后把结论写进 game-ops 和 CLAUDE.md。
