# 外形页按轨迹判 + 训练集核对名单

日期：2026-11-05。状态：设计已和用户逐节确认，待写计划。

## 0. 背景

11-04 晚查清 v10 "好得多"是验证集答案偏向它（见 `docs/progress/2026-09-28-yolo-training.md` 11-04 晚一节）；补全验证集后发现
**YOLO 训练集的人物标注大多没人核对过**：`datasets/sky` 训练集 1449 个人物框里，原有标注只有 3 个在外形页确认过，1300 多个没人看过；
用三个模型（v10 / 多类对照 / v12）估了一下，还有约 210 个漏标候选、34 个三个模型都没框到的可疑标注、91 个只有部分模型框到的。

用户的意见：训练 YOLO 的数据应该尽量人工核对过再用；数据分三个维度（**人 / 交互图标 / 物品**）；标注要省时间——
训练集帧是 8 段录像按 1.5 秒左右一帧切的，相邻帧里还是同一批人，**同一个人连着几帧的裁图应该一起判**。

这一期只做**人**、只优化**判裁图**（外形页），不做整帧画框 / 改框，也不做交互图标和物品的核对（以后照同样思路扩展）。

## 1. 裁图串成轨迹（后端，纯计算）

- **在哪算**：外形页后端（`console/labeling.py` 的外形部分）读 `_crops.jsonl` 时顺手算分组，按 `_crops.jsonl` 的修改时间缓存，新裁了图自动重算；不加命令。
  分组逻辑放进 `vision/attrs_data.py` 旁的新模块 `vision/cropgroups.py`（纯函数，好测）。
- **只在同一来源里串**：同一 `dataset` + `split` + 帧名前缀（`frame_group`，即同一段录像）；收件箱来的（`source = "inbox"`）按同一次运行（`group`）。来源不同永远不串。
- **按时间排**：时间取帧名里的 `_<秒>s`（如 `_175.50s`），取不到时间的裁图各自一组。
- **用 `vision/track.py` 的 `Tracker`**：同一来源里按时间逐帧把裁图的框喂进去（一帧可能有几张裁图），同一条轨迹的裁图 = 一组；相邻两帧时间差 > **3 秒**就断开（重新开轨迹）。
- **一组最多 30 张**，超过切成连续的几段。
- 分组只是"建议一起判"，**不写进任何数据文件**。
- 输出：`groups(rows) -> list[list[str]]`（每组是按时间排的裁图名），每张裁图恰好在一组里。

## 2. 页面（`console/static/labeling.js` 外形部分）

- 顶上加 **「按轨迹」开关**，默认开，状态记在浏览器（`localStorage`，读写包 try/catch）；关掉 = 和现在逐字一样。
- 开着时左边列表 **一条 = 一组**，显示张数；一张的组照旧显示。
- 中间上方一排**缩略图**（这一组按时间），下面照旧大裁图 + 上下文整帧，默认中间那张；点缩略图换成那张的上下文。
- **按键照旧**（1~4 / Enter / 0）：这一组里符合当前筛选、还没确认、没被拆出去的裁图一起标成这一类；已确认的显示成灰色、不动。
- **拆出去**：Shift + 点缩略图（或点角上的 ×）→ 这张不跟这组走、变暗；整组标完后它留在待确认里单独判。拆分只在这次页面里有效，不存盘。
- **Z 撤销**：撤掉刚才整组那一下（见 §3）。
- **筛选照旧**；一组里只要有一张符合筛选就列出这一组，按键只标符合筛选的那几张。
- 新筛选 **「重点核对」**：只显示 `datasets/attrs/_focus.json`（裁图名列表）里、还没人确认的裁图；文件不存在 = 这个筛选不出现。

## 3. 记录、撤销、接口

- **记录**：整组标一次，照旧每张一行 `_labels.jsonl`，多一个字段 `batch`（这一下的编号，同一下的几行相同）。写回 `datasets/sky`、外形头训练、回放答案都读逐张记录，**不改**。
- **撤销**：撤末尾那一下 = 撤掉末尾连续的、`batch` 相同的所有行（挪过的挪回、原地确认的删记录）；没有 `batch` 的旧记录照旧一次一张。
- **接口**：`api/form/state` 多给 `groups`（组 → 裁图名，按时间）和 `focus`（重点核对名单）；`api/form/label` 能收一串裁图名（`names`），一起标、共用一个 `batch`，单张的旧请求照旧可用。
  一串里有不存在 / 已不在原处的裁图：跳过它、照标其余的，返回里列出跳过的。

## 4. 训练集核对名单（离线命令）

- 新命令 `python -m skydango perception crops-audit datasets/sky [--models A,B,C] [--conf 0.25]`（`--models` 逗号分隔，不给就只用 `[perception] model`；这一次用 v10 / 11-04 多类对照 / v12 三个）：只处理训练集、不含增强图。
  - **漏标候选**：任一模型（≥ conf）框出、和标注里任何人物框 IoU < `UNLABELED_IOU`、以前也没裁过的人 → 裁进 `datasets/attrs/_unlabeled/`（模型之间去重），记 `found_by`。
  - **可疑标注**：标注里的人物框，三个模型（≥ 0.15）都没框到；**部分框到**：只有一两个模型框到 → 都进名单。
  - 其余（三个都框到）的标注框过外形头（`[attrs] model`）：最高类不是人形、或人形概率 < `[attrs] accept` 的进名单。
  - 这些框对应的裁图（原有标注的裁图已在 `form/` 里；没有的补裁）写进 `datasets/attrs/_focus.json`（覆盖，旧名单备份成 `_focus-<时间>.json`），并打印各类数量。
- 判完照旧 `perception crops --writeback` 写回（会先备份）。
- 已知局限：这三个模型都在这份训练集上训过，会"记住"训练标注，漏标候选偏少、"三个都框到"不说明对。交叉检查（两半各训一个模型找另一半）以后再做，不在这一期。

## 5. 测试和验收

- 分组：同一段录像连续帧串上；> 3 秒断开；不同录像 / split / 来源不串；没时间的单独一组；> 30 张切段；两个人并排时不串错；每张恰好在一组。
- 后端：整组标注每张一行、`batch` 相同；已确认的不动；不存在的跳过并报出来；撤销整组；旧记录逐张撤销；`state` 带 `groups` / `focus`。
- 页面：沿用 node 跑 `labeling.js` 的测试，覆盖开关、筛选、拆出去、按键作用到整组、关掉开关逐字照旧。
- `crops-audit`：用假检测器 + 小数据集测四类名单和补裁、`_focus.json` 备份。
- **验收（人工）**：核对训练集时数平均每按一下键判掉多少张裁图，目标 ≥ 3；达不到就看是串得太碎还是串错太多。
