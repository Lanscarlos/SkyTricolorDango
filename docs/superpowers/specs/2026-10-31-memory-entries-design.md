# 记忆条目化：日期、事实键、按这句话想起来（设计）

日期：2026-10-31　状态：设计已和用户逐节确认，待审 spec

## 0. 起因和目标

10-31 用沙盒测短期记忆（80 轮，`tmp/memtest/`），和 DSH 社区的两个插件（[Yuuyuko-uu/dsh-fish-memory](https://github.com/Yuuyuko-uu/dsh-fish-memory)、[cron114514/dsh-feiyu-mood](https://github.com/cron114514/dsh-feiyu-mood)）对比后，用户要做四件事，分两批：

- **这一批（本 spec）**：① 事实键，同一件事新的取代旧的；② 按这一轮的话检索，自动带上相关记忆；③ 每条记忆带日期，给大脑看时写成相对时间。
- 第二批（另写 spec）：④ 心情在两次反思之间随时间回落。

要堵的两个真实错误（10-31 沙盒）：

1. **单次的事被整理成喜好**：两次不同上线分别说「早饭吃了榴莲包子」「早饭吃了油条豆浆」，`notes.md` 整理成「早饭爱油条豆浆、榴莲包子」。
2. **分不清是什么时候的事**：inbox 里的日期整理进 notes 后丢了，大脑看到的笔记没有时间。

另外两个问题：notes 整份常驻系统提示词（本机 5.6KB），越长越贵、越乱；最近的事只能靠大脑自己想到去调 `recall`。

成功标准：上面两种错不再出现；notes 变长后，相关的事仍会自动出现在唤醒消息里，系统提示词有上限；用户照旧能手改 `notes.md`。

## 1. 条目格式

`notes.md` 结构不变：`## 人名` 分节（`## 自己` 是团子自己），每行一条。行末可以带一个方括号，里面的字段用「｜」分开：

```
## 番茄炒蛋盖饭
- 养仓鼠，叫芝麻球 〔2026-10-31｜长期｜仓鼠.名字〕
- 下周去青岛出差三天 〔2026-10-31｜出差〕
- 新耳机是粉色猫耳造型 〔2026-10-31〕

## 自己
- 喜欢樱花头 〔2026-09-28｜长期〕
- 无翼，跑图容易出事
```

- **日期** `YYYY-MM-DD`：这条**最后一次被提起或确认**的日期。
- **长期**：喜好、习惯、设定、关系、约定。没有这个标记的是**近况**（一次性的事、最近在忙的事）。
- **键**（可选）：「对象.方面」或一个短词。同一节内键相同的视为同一件事。
- 字段顺序固定为 日期｜长期｜键，长期和键都可以省略；`长期` 是保留字，不能当键。
- **没有方括号的行**（手写的、旧笔记）= 长期、日期不详。上线后行为和现在一样（照旧常驻）。
- **方括号写坏的行**（日期解析不了等）：整行当正文，按长期、日期不详处理，不丢内容，记 DEBUG。
- `inbox.md` 用同一格式，每行 `- 谁：内容 〔…〕`（「谁」是游戏昵称或「我」）。

新模块 `src/skydango/chat/entries.py`（纯函数，无 I/O）：
- `Entry`：所在节、正文、日期（可空）、长期、键、原始行。
- `parse_notes(text) -> list[Entry]` / `parse_inbox(text) -> list[Entry]`：inbox 的「谁：」决定所在节，「我」归 `自己`。
- `render_notes(entries) -> str`：写回 `notes.md`，保持分节顺序。
- `show(entry, today) -> str`：给大脑看的样子，去掉方括号，日期写成相对时间：今天 / 昨天 / N 天前（≤ 13 天）/ 上个月 10-02、9 月 26 日（同一年）/ 去年 09-17 / 2024 年 9 月 17 日；日期不详就不写。

## 2. 写入、取代、淡出

**写入**还是现有的两步（`chat/memory.py` 的 `NotesKeeper`），只改提示词：

- **随手记**（`MEMO_SYSTEM`，每轮一次）：每条输出 `- 谁：内容 〔日期｜长期｜键〕`。相对时间照旧换成具体日期。
- **整理**（`NOTES_SYSTEM`，每 `notes_every` 轮）：把新聊天和 inbox 并进 notes，整份按新格式重写。新增几条规则：
  - **什么才算长期**：本人说成习惯、喜好、设定的，或者在**不同的两天**都提起过的。只说过一次的具体事件一律记成近况，**不许把几次单独的事合并成喜好**（「早饭爱 X、Y」就是这种错）。
  - 同一件事再次被提起：日期改成最新那天。
  - 会变的事（名字、发型、计划、在忙什么……）给一个键；新的说法和旧的同键时，只写新的。
  - 「每条不超过 30 字」照旧；「整份不超过 1500 字」改成只约束**长期**部分。

**代码兜底**（`entries.py` 的 `settle(old, new, today, cfg) -> (keep, archived)`，整理拿到模型输出后、写盘前调用；不依赖模型自觉）：

1. **取代**：同一节、键相同的，留日期最新的一条（一样新就留模型新写的那条），其余进 archive，原因「被取代：<新正文>」。
2. **补日期**：新条目没日期时，找旧笔记同一节里文字相似度 ≥ 0.8 的那条（`difflib`），补它的日期。
3. **近况淡出**：近况的日期距今超过 `recent_days`（默认 30）进 archive，原因「近况过期」。长期的不按时间淡出。
4. **长期超上限**：常驻部分（全部长期条目渲染后）超过 `pinned_max`（默认 1500 字）时**不删**；按日期从旧到新（日期不详的算最旧，`## 自己` 最后才动）把超出的那些标为「不常驻」（只在内存里，见 §3），日志 INFO 一行提醒。

**archive**：`memory/notes_archive.md`，按挪走的日期追加，格式 `- 〔挪走 2026-10-31：原因〕原始行`。`recall` 照样能翻到；用户可以手动挪回去。

**整理结果把关**（现在没有，顺手加）：新输出里能解析的条目数不到旧条目数的一半（旧的 ≥ 6 条时），或者超过一半的非空、非标题行解析不了 → 拒绝写盘，沿用旧 notes，WARNING 一行。

**inbox 消化**不变（`consume_inbox` 按快照删已经整理的部分）。

## 3. 怎么带给大脑

### 3.1 系统提示词（上线时生成一次）

`brain/prompt.py` 里原来 `notes = store.notes()` + 「刚记下的：」+ inbox 的那段，改成：

- 「记得的事」：notes 里**常驻**的条目（全部长期条目，除了 §2 第 4 条 被标为不常驻的），按节分组，用 `show()` 渲染（相对日期按上线那一刻算）。
- inbox 里标了长期的也并进这一节。
- 近况、inbox 里没标长期的**不进系统提示词**，进 §3.2 的候选池。

系统提示词在一次上线内不变（前缀缓存），这一点不动。

### 3.2 每轮唤醒消息：「想起来的：」

新模块 `src/skydango/brain/recollect.py`：`Recollector`，身体线程里用，经 `body.call` 取，和「回法：」一样放在唤醒消息「状态：」前面（`Brain.message`）。

- **候选池**（上线时建，整理写盘后、inbox 变了时重建）：所有近况条目、§2 第 4 条 不常驻的长期条目、上线时 inbox 里没标长期的条目。上线中途新记的 inbox 照旧走「你刚记下：」（`compact.InboxWatch`），不进池子，免得重复。
- **打分**（每条，取这一批事件）：
  - 人：条目所在节是这批里说话的人、`arrive` / `return` 的人 → +2；是 `自己` 且这批有人跟团子说话（addressee me / all）→ +0.5。说话人按 friends.md 的标题和 `- 叫法：` 模糊匹配（复用 `brain/addressee.py` 的 `parse_aliases`）。
  - 话：这批聊天原文和条目正文的**两字片段**（去掉标点、单字不算）重合个数，每个 +1，最多 +3。
  - 新：`0.5 ^ (天数 / half_days)`，`half_days` 默认 14；日期不详按 0.3。
- **门槛**：「人」和「话」都是 0 的不带；总分 < `min_score`（默认 2.0）不带。
- **上限**：一轮最多 `per_turn`（5）条、`turn_chars`（400）字，按分数从高到低取。
- **一次上线只带一次**：带过的记下 key（节 + 原始行），这次上线不再带；大脑历史**压缩换上**后清空这份记录（原话没了，可以再带）。Claude 大脑没有我们的压缩，不清空。
- **好友来了**：`arrive` 事件的人，先把他那一节最新的 3 条近况（不管话题）放进这一轮，再按上面的打分补满。
- 格式：
  ```
  想起来的：
  - 番茄炒蛋盖饭：下周去青岛出差三天（10 天前）
  - 番茄炒蛋盖饭：养仓鼠，叫芝麻球（10 天前）
  ```
- 什么都没带就不写这一段。出错只记日志，这一轮不带。

### 3.3 其他用到 notes 的地方

- **反思材料**（`Body` 第 3088 行附近）：原来按「行里有没有他的名字」筛，好友的条目写在 `## 名字` 下面、行里不带名字，基本取不到（现有 bug）。改成按节取相关好友的条目，`show()` 渲染，每人最多 10 条。
- **`recall`**（`chat/recall.py`）：附带的笔记行用 `show()` 渲染，并带上 `notes_archive.md` 里匹配的行（标「（以前的）」）。
- **随手记、整理时给模型看的「已经记下的」**：给原始行（带方括号），模型才能接着按格式写。
- **`--no-brain` 的普通 Agent**（`chat/responder.py`）：照旧整份带，用 `show()` 渲染。
- **`memory show`**：打印渲染后的样子，另外打印常驻 / 候选池各多少条、多少字。

## 4. 配置、迁移、出错

`[reply]` 下新增（管理面板设置页给 `memory_entries` 开关和三个数字）：

| 项 | 默认 | 说明 |
|---|---|---|
| `memory_entries` | `true` | 关掉逐字照旧：旧整理 / 随手记提示词、整份常驻、不检索、反思照旧按名字筛 |
| `recent_days` | 30 | 近况多少天没被提起就进 archive |
| `pinned_max` | 1500 | 常驻部分最多多少字 |
| `recall_per_turn` | 5 | 每轮最多带几条 |
| `recall_chars` | 400 | 每轮最多带多少字 |
| `recall_half_days` | 14 | 新鲜度半衰期（天） |
| `recall_min_score` | 2.0 | 门槛 |

**迁移**：不写迁移脚本。旧笔记没有方括号 = 长期、日期不详，行为和现在一样。`memory_entries` 打开后**第一次整理前**把 `notes.md` 复制到 `memory/archive/notes-<时间>.md`（`notes_state.json` 记一个 `entries_since`，有了就不再备份）。第一次整理时模型按新格式重写；旧条目看不出日期的，写这次整理的日期。

**出错**：解析 / 渲染 / 检索出异常只记日志，那一处退回照旧的样子（系统提示词退回整份 notes 原文、这一轮不带「想起来的」）。整理把关见 §2。

## 5. 测试

单元测试（合成数据，不调模型）：

- `entries.py`：解析三个字段的各种组合、省略、坏方括号、没方括号；inbox 的「谁：」和「我：」；`render_notes` 往返不变；`show()` 的今天 / 昨天 / N 天前 / 上个月 / 同年 / 去年 / 跨两年。
- `settle`：同键留最新、一样新留新写的；补日期（相似 ≥ 0.8 才补）；近况过期进 archive；长期超上限只标不常驻、`自己` 最后动；archive 的行格式。
- 整理把关：条目骤减一半、解析失败过半 → 不写盘。
- `Recollector`：人 / 话 / 新三项打分；门槛；上限按分数截；一次上线只带一次；压缩换上后清空；`arrive` 先带最近 3 条近况；什么都没有时不出这段；叫法匹配。
- 系统提示词：常驻条目渲染进「记得的事」、近况不进；超上限时长度被卡住。
- 反思材料：按节取到好友条目（现有 bug 的回归测试）。
- `memory_entries = false`：系统提示词、唤醒消息、整理和随手记的提示词与现在逐字一样（把现在的输出存成基准文件对照）。

沙盒验证（真 DeepSeek，`sandbox-ctl`）：

1. 一次上线让好友说「早饭吃了榴莲包子」，下线；再上线说「早饭吃了油条」，触发整理（`memory update` 或攒够轮数）。notes 里不能出现「爱吃 / 喜欢吃」这类喜好；应该是同键取代后只剩油条，或两条各带日期的近况。
2. 在 notes 里手写一条 10 天前的近况，让好友说起相关的事：唤醒消息里有「想起来的：」带上这一条、写「10 天前」。
3. 把 notes 塞到 3000 字：系统提示词里「记得的事」不超过 `pinned_max`，被挪出的条目被提起时仍能出现在「想起来的」里。
