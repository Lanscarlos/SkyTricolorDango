# 读聊天改用无障碍节点（面板 + 头顶气泡）— 设计

日期：2026-10-04　状态：**设计已和用户确认，待写计划**

前置：`device/a11y.py`（读无障碍节点的读取器，已合并，`a5569ca`）；实测记录见 game-ops §3「无障碍节点」和本文 §1。

## 目标

读聊天不再 OCR 截图，改读光遇镜像出来的无障碍节点（文字 + 屏幕坐标）：

- **准**：说话人、原文直接拿到，没有错字；现在为 OCR 打的补丁（淡入帧读成乱码、底部被裁、折行拼接、省略号被吃、自己的浅色气泡当成输入框）都绕开
- **面板不用一直开**：好友在画面里说话，从他头顶的气泡就能读到原文，还能看出他在打字；聊天面板只在说话的人不在画面里时才需要开，团子可以像真人玩家一样关着面板聊天
- **对外接口不变**：身体 / 普通 Agent 照样每圈 `reader.read(frame, now)`，面板管理器、大脑、记忆、反射不用跟着改

成功的样子：dry-run 里好友站在画面里说话，面板一直关着，`rows.log` 里一字不差地读到、说话人对；他走到画面外说话，15 秒内被"看一眼"接住；
`--live` 时团子关着面板回话；读取器被别的工具抢走连接时自动重启，最后退回 OCR，聊天照读。

## 需求（已和用户确认）

1. 范围是**面板 + 头顶气泡**：面板开着读面板行，面板关着读好友头顶气泡
2. 无障碍读不到时**自动退回 OCR**：`[vision] source = "a11y"`（默认）/ `"ocr"`；现有 OCR 读法原样保留
3. 跟画面里的好友聊天时**面板关着**，说话的人不在画面里才开面板
4. 不在范围里：头顶名字标签给感知层认人；用输入栏节点核对发送内容

## 1. 实测事实（2026-10-04 上午，MuMu Android 12L，测试脚本和日志在本机 `tmp/a11y-live/`）

- 游戏在渲染画面上盖了一层不可见的原生 View（`app:id/system_ui_view`），把 UI 文字镜像成 `TextView`；类名都是 TextView、没有 view id，只能按坐标和格式分
- **面板开着**：每一行一个节点，格式和画面一样是「内容 - 说话人」，**往上滚出去的历史行也在**（`isVisibleToUser = false`，坐标被裁成怪值，如 `[21,0,188,-954]`），顺序从上到下；
  别人的行贴左（x1 ≈ 13~22）；**团子自己的行贴面板右边、没有说话人**（如 `[559,936,618,976]`）；折行的长消息是一个节点；左下角占位 `聊天……` 在 `[77,1021,154,1051]`；
  面板刚打开时行先以"看不见"、很小的框出现（`[13,301,52,311]`），约 0.3 秒后变看得见，**文字一开始就是全的**
- **面板关着**：只有头顶的名字标签和气泡。说话的人头顶，名字标签在最上面（高 42 px），下面一摞是他最近几句（每行高 38 px，折行时 72、140……），
  **一句一个节点，x 中心和名字标签对齐**（实测 1053 / 1053）；陌生人没有名字标签、气泡全是点点；画面外的气泡是"看不见"
- **气泡的时间线**：对方开始打字 → 头顶冒一个只有点点的气泡（`.` → `..` → `...` 循环）→ 发出来变成原文气泡（第一份快照"看不见"，约 0.17 秒后看得见，**刚出来时是干净的原文**）→
  他接着打下一句时，最新那条气泡后面挂上循环的点（`怎么样..` → `怎么样...` → `怎么样 ..` → `怎么样`）→ 每句在头顶留 20 多秒淡掉
- **团子自己**：头顶同样先冒点点再出原文气泡（没有名字标签）；面板里是贴右的一行
- **输入栏**：输入框打开时多一个横贯屏幕底部的节点 `[14,962,1906,1032]`，文字是占位 `聊天……` 或打进去的字，关上就没了
- 读取器连着时 Enter 正常打开输入框（重启游戏后连按三次都 0.1 秒内打开）；上午一度怎么都打不开输入框是游戏自己卡住了（用户手动也打不开，重启好了），和无障碍无关
- 屏幕下方的操作提示（"点击您的角色发出呼唤"）不在树里：不是所有 UI 文字都有镜像

## 2. 组成和数据流

```
device/a11y.py（已有）A11yReader：设备上常驻客户端，后台线程收快照
        │  latest(max_age) → Snapshot（节点：文字、坐标、看不看得见）
        ▼
vision/a11yui.py（新，纯计算）classify(snapshot, width, height, friends) → UiView
        │  面板行 / 名字标签 / 气泡（按列挂好说话人）/ 输入栏 / 面板占位
        ▼
chat/a11yreader.py（新）A11yChatReader：接口同 ChatReader，带状态（面板对齐、气泡跟踪、去重）
        ▼
chat/a11yreader.py FallbackReader：a11y 不行就整次 run 换成 OCR 的 ChatReader
        ▼
身体 / 普通 Agent / PanelManager / 识别可视化：照旧调用
```

- `ChatReader`（OCR）不改，兜底时用；沙盒世界自己的假 reader 不受影响
- `Message` 加一个默认为空的字段 `source`（`"panel"` / `"bubble"`），其余不变；面板管理器靠它区分，老代码不用改
- `cli._build_reader` 按 `vision.source` 建 reader；`run`、`view` 都走它

### 2.1 分类规则（`vision/a11yui.py`）

坐标按 1920×1080 量，换算成比例存常量；写计划时拿本机录像回放再校一遍。只用当前窗口包名是光遇的快照，别的（系统弹框、游戏重启中）当成"什么都没看到"。

| 类别 | 规则 |
|---|---|
| 输入栏 | 宽度超过屏幕 90%、在屏幕最下面一条；文字是占位或打进去的字 |
| 面板占位 | 文字是 `聊天……`、在左下角、宽度不到屏幕 15% |
| 面板行（别人的） | x1 在面板左边距内（≈ 30 px 以内）、x2 在左三分之一里，文字能按最后一个 " - " 拆出说话人；内容全是点点 = 被屏蔽（陌生人） |
| 面板行（自己的） | 面板开着时，x2 贴着面板右边（≈ 面板右沿往里 30 px 以内）、x1 不贴左、没有 " - " |
| 名字标签 / 气泡 | 其余在 3D 画面区域的节点。按"列"分组：x 中心相差 25 px 以内、竖着挨着。一列里最上面那个、单行（高 ≈ 42）、文字精确对得上好友名单（friends.md 的 `## 标题`）的是名字标签，其余是气泡 |

- 面板开没开：面板占位看得见，或者有看得见的面板行
- 好友的气泡里刚好说了另一个好友的名字：只有最上面那个才可能是标签，下面的永远算气泡
- 只用"看得见"的名字标签和气泡（画面外的不要）；面板行看不看得见都用（对齐要整段历史）

## 3. 判断新消息（`chat/a11yreader.py`）

### 3.1 面板行（面板开着时）

- 每份快照把面板行（连滚出去的）排成一列，每行的比较键是（自己 / 说话人 / 原文）**精确相等**
- 对齐：在新的一列里找和"上一列末尾"往上连续对上最多的位置，它下面的是新行（同 `chatlog.new_rows` 的思路，换成精确比较；同一句连说两遍按位置对，不会被吞）
- 面板关着时**不清基准**：再打开时，关着那段时间进来的行照样对得出来
- 一行都对不上（刚启动、换场景、重新登录清了历史）：当新基准、不报，记 INFO —— 和现在一样，宁可漏一句也不把整屏历史当新消息
- 淡入不用等：文字一开始就是全的。`settling` 恒为假
- 报之前过滤：被屏蔽的行、自己的行不报；`SelfFilter`、`chat.ignore_patterns`、`ocr.min_chars` 照旧过一遍（`min_chars` 同样适用，免得一个字的噪声）
- `rows.log`：面板行每次变化记一笔（同现在的格式），`*` 标新行

### 3.2 头顶气泡（面板关着时）

- 每个说话人（名字标签的文字）记住"他头上现在有哪几句、各几次"；**比较时去掉末尾的打字动画**：比较键 = 原文去掉末尾的一串空格和半角点（`[ .]*$`），
  所以 `怎么样..`、`怎么样 ..`、`怎么样` 是同一句（代价：只差末尾几个点的两句话当成同一句，可以接受）
- 冒出一句以前没有的（或者同一句出现的次数变多了）→ 新消息，`speaker` = 名字标签，原文用**这句第一次出现时的样子**（去掉首尾空白），`box` = 气泡的框，`source = "bubble"`；
  照样过 `SelfFilter`、`ignore_patterns`、`min_chars`
- 只有点点的气泡挂在好友名下 = 他在打字：记下"谁、什么时候"，给状态和面板用（§4）；陌生人列的点点不管
- **挂不上名字标签、但有原文的气泡**：
  - `SelfFilter.is_self` 认得出（团子自己刚说的）→ 丢掉
  - 否则（好友离远了、标签淡掉了）→ 不报，记一个"想看一眼面板"的原因，由面板行带着说话人报出来
- 面板开着时**不从气泡报消息**：每份快照都把当前气泡记成"见过"，面板一关，这些旧气泡不会被当成新的
- 刚启动的第一份快照：现有气泡全部记成"见过"

### 3.3 两边读到同一句

- 从气泡报过的话进"最近报过"清单（说话人 + 原文，留 180 秒）
- 面板对出新行时，清单里有说话人相同、原文相同（都去掉首尾空白后精确相等）的就**划掉一条、不报**（一条抵一条：同一句说了两遍、气泡只报了一遍，面板里第二遍照样报）
- 面板开着时只认面板行（§3.2），所以不会出现"面板先报、气泡又报"

## 4. 和面板 `auto` 模式的配合（`chat/panel.py`）

reader 多给面板管理器三样东西（OCR 的 `ChatReader` 没有这些属性，面板管理器用 `getattr` 取，没有就当 OCR 模式）：

- `reads_bubbles`：现在能不能读气泡（a11y 正常时为真；兜底切回 OCR 后为假）
- `tags_in_view()`：现在看得见哪些名字标签
- `want_peek()`：有没有要看一眼面板的原因（挂不上名字的原文气泡），取一次就清掉

新增状态 **「聊着（面板关着）」**（`talking`），原来的 闲着 / 看一眼 / 等气泡 / 聊天中 都保留：

| 情况 | 现在 | a11y 模式（`reads_bubbles` 为真） |
|---|---|---|
| 读到的新消息全是 `source = "bubble"` | 进「聊天中」、开面板 | 进「聊着」，不开面板；记下跟谁聊（`_talk_with`） |
| 读到 `source = "panel"` 的新消息 | 进「聊天中」 | 不变：进「聊天中」，面板开着 |
| 「聊着」时 | — | 每 `chat_peek`（15 秒）看一眼面板（接住画面外的人）；`quiet_close`（45 秒）没动静回闲着 |
| 团子要说话 `before_speak` | 进「聊天中」、开面板 | 在「聊着」、而且 `_talk_with` 的名字标签都还看得见 → 不开面板，刷新活动时间；否则照现在开面板、进「聊天中」 |
| 好友在画面里打字 | YOLO `typing_seen` → 进「等气泡」、开面板等 | 身体不再拿 `typing_seen` 叫面板（`reads_bubbles` 为真时跳过）；打字只写进 status |
| `want_peek()` 有原因 | — | `trigger("bubble_text")`，照现在的看一眼流程 |
| 中途兜底切回 OCR | — | 「聊着」立刻改成「聊天中」、开面板，之后全照旧 |

- 「看一眼」读到 `source = "panel"` 的新消息照旧进「聊天中」（说话的人多半在画面外）
- `describe()`：「聊着（面板关着，12 秒后看一眼）」；status / 管理面板照常显示
- `[panel] mode = "always"`（沙盒、老测试）完全不受影响：常开模式下气泡也不用来报消息（面板开着只认面板行）
- 身体 `say` 之外调 `before_speak` 的地方（反射替大脑开输入框）同样按上表

## 5. 兜底和出错处理（`FallbackReader`）

- **启动**：`vision.source = "a11y"` 时起 `A11yReader`；起不来（推不上 jar、`already registered`、没有 adb）→ 直接用 OCR，WARNING 写明原因
- **中途客户端死掉**：自动重启，最多 3 次，间隔 2 / 5 / 10 秒（成功收到快照就把计数清零）。重启期间：`read()` 返回空，`panel_visible()` 借 OCR reader 判断（看截图里的输入框，便宜），免得面板管理器乱按键
- **3 次都失败，或 30 秒没收到快照**（心跳每秒一份，`latest(max_age=…)`）：这次 run 剩下的时间整个切到 OCR，WARNING + status「读聊天：OCR（无障碍读不到：原因）」；切换期间漏的那几句不补；OCR reader 从空基准开始，不会把历史当新消息
- 当前窗口不是光遇：算"什么都没看到"（面板关着、没有气泡），不算故障
- **收尾**：`run` / `view` 的每条退出路径（Ctrl+C、管理面板停止、`--duration` 到点、出错）都 `stop()`，清掉设备上的进程
- 同一时间只能有一个无障碍连接：`view` 和 `run` 同时开时，后起的那个退回 OCR
- `vision.source = "ocr"`：逐字照旧，不起读取器

## 6. 配置

- `[vision] source = "a11y"`（`"ocr"` = 现在的读法）
- `[panel] chat_peek = 15.0`（「聊着」时多久看一眼面板）
- 管理面板设置页加 `vision.source`；`config.example.toml` 写注释

## 7. 测试（`python -m pytest`，不用模拟器）

**公开仓库不能放真实聊天和好友昵称**：测试数据按 §1 量到的坐标手写合成快照（假名字）。本机 `tmp/a11y-live/` 的真实记录另写一个回放测试，文件不在就跳过。
（要回放就得有原始快照：给 `a11y --watch` 加 `--save 文件` 把原始 JSON 行存下来，今晚真机验证时顺手录一份。）

- `a11yui`：各类节点归类；滚出去的行；画面外的气泡；气泡说了别的好友名字；包名不是光遇
- 面板对齐：追加新行、同一句连说两遍、顶上旧行滚掉、对不上当新基准、关上再打开后补报、自己的行和被屏蔽的行不报
- 气泡：新气泡、打字动画不算新消息、同一句连发两遍、只有点点 = 在打字、挂不上名字 → `want_peek`、团子自己的被 `SelfFilter` 过滤、面板开着时不报、启动时的旧气泡不报
- 去重：气泡报过的那句开面板后不再报；一条抵一条
- 面板状态机：「聊着」的进出、`chat_peek`、`before_speak` 开不开面板、兜底切换时改成「聊天中」、always 模式不变
- `FallbackReader`：用假读取器模拟起不来、中途死掉、重启成功（计数清零）、3 次失败后切 OCR、30 秒没快照切 OCR、收尾 `stop()`

## 8. 真机验证（晚上做）

1. `python -m skydango a11y --watch 30 --save tmp/a11y-live/raw.jsonl`：面板开 / 关、好友说话、团子说话各录一段（给回放测试用）
2. `run --view` dry-run：好友在画面里说话，面板一直关着，消息从气泡读到、说话人对；`rows.log` 里看得到；状态显示「聊着」
3. 好友走到画面外说话：15 秒内被"看一眼"接住，进「聊天中」开面板
4. `--live`：团子关着面板回话，好友的回复照样读到；面板开着时团子说话、好友回复，不重复读
5. 运行中另开一个 `python -m skydango a11y` 抢连接 / `pkill -f '^skydango-a11y'`：看到重启；连续抢 3 次后切 OCR，聊天照读
6. 停下后设备上（`ps -A | grep skydango`）和本机都没有残留进程

## 9. 风险

- **分类规则靠坐标**：游戏更新改了界面布局，规则会失效 —— 回放测试会先挂；读不到时有 OCR 兜底
- **游戏能察觉有无障碍客户端连着**：和任何读法一样，用户知情
- **名字标签淡掉**（好友稍远）：他的原文气泡挂不上名字，只能靠看一眼面板，比画面里的好友慢；按 Q 喊一声会让标签亮出来（已有 `[call]`），这次不联动
- **头顶一摞气泡挡住名字标签 / 两人站得很近**：列分组可能挂错人 —— 25 px 的容差待真机核对，挂错时的后果是说话人写错，记进 `rows.log` 便于排查
