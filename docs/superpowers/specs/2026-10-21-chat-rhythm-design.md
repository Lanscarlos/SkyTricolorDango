# 聊天节奏像人：短句多等一会儿 + 按真实时间线回放验收（`[pacing] short_quiet`）

2026-10-21 沙盒验收（`runs/20261021-195520-sandbox`）里，卡洛单聊时团子还是几乎句句回（60 句回了 52 句）。
10-07 定的 `[pacing]`（spec `2026-10-07-chat-pacing-design.md`）把「回法」当建议摆给大脑，DeepSeek 基本不照做。

这次 brainstorming 时看了 10-07 晚的真机时间线（`runs/20261007-220825-live-brain`，那时还没有 `[pacing]`），结论：

- **那晚基本是严格的一来一回**：卡洛说一句，团子 3~4 秒就回，卡洛看完回复 10~15 秒后再说下一句。对方在等团子开口，只管时机攒不到第二句。
- **真正的连发不多**，大多已经只回了一句（「诶诶诶 / feiwu是敏感词啊 / 不能发」）；拆开回的是「嘻嘻」+ 2 秒后「团子」这种。
- **10-21 沙盒的 52/60 测高了**：`sandbox-ctl say` 每句都等团子回完才发下一句，话永远攒不起来。

## 用户定的方向（brainstorming 时选的）

- **代码只管时机**：不替大脑决定说不说、不拦 `say`；只让它晚一点醒、攒得多一点。
- **最多等多久**：对方说完最后一句到团子开口，一般不超过 8~10 秒。
- **成功标准改成「节奏像人」**，不再追「回复数减半」（一来一回时句句接，真人也这样）：
  1. 对方说完到团子开口一般 5~10 秒，不会 3 秒秒回（问句、叫团子、难过照旧快）
  2. 连发的几句（含「嘻嘻」+ 几秒后「团子」）只回一次
  3. 单独的短句（嗯 / 哈哈 / 嘻嘻 / 哦）多等一会儿，后面还有话就并成一批
- 方案选 A（短句多等 + 回放验收）；按对方打字节奏自适应（B）、短句不叫醒大脑（C）不做。

## 非目标

一来一回时少接几句（要代码拦话或换模型，这次不做）；贱的分寸、回法提示（不改）；多人聊天跟谁说（`[addressee]`）；主动开口（`[proactive]`）。

## 1. 短句多等一会儿（`brain/pacing.py`）

`Pacer` 判放行时用的安静时长改成「有效安静时长」：

- 攒着的这批**全是短句**时，取 `max(这批原来的 quiet, short_quiet)`；进来一句不是短句的，回到原来的 quiet（问句照旧取 `quiet_min`）。
- **短句** = 去掉空白不超过 `[pacing] short_len`（6，和回法共用）个字，并且不是问句（`is_question`）、没说难过（`sounds_upset`）、没叫团子（包含 `[proactive] self_names` 里任何一个）。
  「团子」单独一句是在叫它，照旧按原来的 quiet 放。
- 上限照旧：第一句进来满 `max_wait`（15 秒）一定放；urgent（难过、卡洛的 `#` 命令）马上放；对方在打字照旧从最后看到打字起重新算。
- `describe()`（status「在攒话：…再等 N 秒」）按有效安静时长算。

`Pacer(cfg, rng, self_names=())`：身体建它时传 `cfg.proactive.self_names`。不传 = 没有名字算叫团子（单元测试用）。

## 2. 配置（`config.py` `[pacing]`）

- `short_quiet: float = 8.0`：全是短句的一批，最后一句后至少安静这么久才放。**0 = 关**（逐字照旧）。
- 管理面板设置页加 `pacing.short_quiet`；`config.example.toml` 写一行说明。

## 3. 按真实时间线回放（`sandbox-ctl play`）

新子命令 `python -m skydango sandbox-ctl play <文件> [--timeout 秒]`：按文件里的时间点把话发进沙盒，**不等团子回完**，最后一句发完再等到 idle（同 `say` 的等法），打印这段时间的聊天新行和大脑每一轮的文字。

文件格式：一行一句，`<秒> <说话人>：<原文>`（秒 = 相对第一句的偏移，可以带小数；全角 / 半角冒号都行；空行和 `#` 开头的行跳过）。说话人要先 `come` 到身边（`play` 不替你 `come`）。格式不对的行报行号、整个文件不发。

每句发出时打印 `+12.3s 说话人：原文`，方便和团子的回复对时间。`--json` 时输出 `{"sent": [...], "lines": [...], "turns": [...]}`。

## 4. 验收

1. 从 `runs/20261007-220825-live-brain/agent.log` 取卡洛的话（INFO `跟谁说` 行），按原时间写成回放文件，放 `tmp/`（**不进 git**：有聊天原话）。重复读到的同一句（10-07 修过的那个 bug）去掉。
2. 沙盒起来、`come 懒洋洋大王`、`play` 这个文件，`short_quiet = 0` 和 `= 8` 各跑一遍。
3. 用 `agent.log` 的「跟谁说」行和「已发送」行（沙盒是 transcript）算三个数：
   - 对方最后一句到团子开口的延迟分布（目标：中位数 5~10 秒，问句 / 叫团子 / 难过以外没有 < 4 秒的）
   - 间隔 ≤ 有效安静时长的连发被拆开回了几次（目标：0）
   - 后面 8 秒内还有话的短句，有几次没和下一句并成一批（目标：0）
4. 结果写进 `docs/progress/` 当天的进度文档；真机上之后再看一次单聊。

## 5. 测试

- `tests/test_pacing.py`：全是短句等 `short_quiet`；中途来一句长句 / 问句回到原 quiet；「团子」不算短句；难过 / urgent 照旧马上放；`max_wait` 上限；`short_quiet = 0` 逐字照旧；`describe` 的秒数。
- `tests/test_brain_pacing_body.py`：身体建 `Pacer` 时传了 `self_names`（「团子」单独一句不按短句等）。
- `tests/test_sandbox_ctl.py`：`play` 解析（偏移、全半角冒号、注释、坏行报行号不发）、按时间点发（假时钟 / 假 sleep）、不等回完、最后等 idle、`--json`。

## 6. 已知限制

- 一来一回时还是句句接（用户接受，见上）。
- 沙盒没有「在打字」信息，回放只测得到时间部分；真机上对方在打字时会等得更久。
- 数字（`short_quiet` 8 秒）是按 10-07 一晚估的，真机再看。
