# 聊天记录面板按需打开 — 设计

日期：2026-09-29　状态：**设计已确认，待写实现计划**

现在聊天记录面板（光遇里按 C）一直开着：`chat/panel.py` 的 `PanelKeeper` 发现它关了 5 秒就重开；
转镜头、换轮盘、接互动、好友树四处各自"先关面板 → 做事 → 再开"。
这份设计把面板改成**平时关着、有需要才开**，由一个管理者统一决定开关。

## 目标

面板开着时方向键转视角、`-` / `=` 拉近拉远、长按 Z、Q 都没反应，面板还挡住 3D 画面左边三分之一（game-ops §2、§5）。
按用户排的优先级，关掉面板换来：

1. **（A，最优先）技能和镜头不被面板卡住**：`look_around` / `spin`、以后的 `track` / `approach` / `follow`、拉远看全景
2. **（B）YOLO 看到完整画面**：感知层不用再跳过左边那块
3. **（C，顺带）更像真人**：真人不会一直开着聊天记录

成功的样子：没人说话时面板关着，技能随便转镜头；画面外的好友说话，半分钟内读到；一聊起来面板就开着、回复和现在一样快；
转镜头 / 换轮盘 / 接互动之后面板回到该有的状态，不会"该开没开"读不到聊天，也不会在面板关着时按 C 打出字母 c。

## 需求（已和用户确认）

1. **聊天内容只从聊天记录面板读**。YOLO 不认聊天内容；面板关着时只判断"是不是有新消息了"
2. **面板关着时新消息照样进记录**（用户确认），重新打开能读到；`ChatReader` 关着时保留上一次的行（`_prev_keys`），重开后对齐就能找出新消息，读消息的逻辑不用改
3. **游戏在面板关着时没有新消息提示**（用户确认）→ 发现新消息只有两条路：YOLO 看到头顶气泡（只对画面里的人）、定时打开看一眼（兜底）
4. **按"在不在聊天"切换两种状态**（方案 1）：闲着时面板关、每 30 秒看一眼；聊天中面板开着；数字先用默认值
5. "看一眼"没读到新消息就立刻关，不多停
6. 先加开关、**默认保持现在的常开**（`mode = "always"`），真机验收通过后再把默认改成 `"auto"`
7. 陌生人的气泡默认不触发（没解锁聊天的陌生人在面板里只有省略号）
8. 技能执行期间面板借出、不读聊天，最坏晚 60 秒（技能最长 60 秒），第一版接受
9. 团子在"闲着"时主动开口：先开面板、进"聊天中"，再按 Enter（慢约 1 秒，换来能立刻读到回复）
10. 普通 Agent（`run`）和大脑（`run --brain`）都用；好处主要在大脑模式（技能层只在那里）

## 方案选择

**选定：方案 1，按"在不在聊天"切换状态**（本文 §1~§5）。

放弃的方案：
- **2. 固定周期**：一直关着，每 10~15 秒看一眼 + 气泡触发。最简单，但聊得正热时也要等周期，技能每 10~15 秒被打断一次
- **3. 默认开着、只在技能时借走**：只统一开关，A 只满足一半（长技能期间照样读不了），B 完全得不到
- **YOLO 读聊天内容**（框出头顶气泡再 OCR）：气泡米色半透明、常和白色角色 / 光效连成一片（game-ops §3 早就放弃过），
  先显示 `..` 几秒才出字、连发排队、几秒就消失，要人在画面里没被挡，远处小、有透视，没有说话人和先后顺序。
  分工改成：YOLO（`typing` 类）回答"谁在说话、该去看了"，面板回答"说了什么"

## 1. 状态机（`chat/panel.py` `PanelManager`）

`PanelKeeper` 扩展成 `PanelManager`（保留 `ensure_open()`），**唯一**有权按 C 开关面板的地方。
每圈由身体（`Body._sense`）/ Agent 主循环调一次 `tick(frame, now, fresh)`（`fresh` = 这一圈 `reader.read()` 的结果），
和设备在同一个线程，不另开线程、不加锁。

| 状态 | 面板 | 进入 | 离开 |
|---|---|---|---|
| **闲着** `idle` | 关 | 启动时；聊天中连续安静 `quiet_close`（45 s） | 定时到或有触发（§2）→ 看一眼 / 等气泡 |
| **看一眼** `peek` | 临时开 | 定时、`arrive` / `approach`、大脑调 `chat_log` | 读一帧：有新消息 → 聊天中；没有 → 关，回闲着 |
| **等气泡** `bubble` | 临时开 | 好友头顶冒出"正在输入"气泡 | 读到新消息 → 聊天中；气泡消失 `bubble_gone`（3 s）后仍没有，或开了 `bubble_wait`（15 s）→ 关，回闲着 |
| **聊天中** `chatting` | 开 | 读到新消息；团子要说话（§4）；意外发现面板开着（§5） | 连续 `quiet_close` 秒"安静" → 关，回闲着 |
| **借出**（叠加） | 关 | `borrow()`（§3） | 归还：回到借出前那个状态该有的样子 |

- **新消息** = `reader.read()` 返回的消息（已经排除了团子自己的、被屏蔽的陌生人行、太短的、忽略规则命中的）
- **安静** = 这段时间里：没有新消息、团子没说话、没在准备回复（Agent 在攒消息 / 等模型，大脑有待回复的聊天事件）、输入框没开（`ime_shown()`）。
  任何一项不满足就把安静计时清零。"在准备回复"由调用方告诉管理者：`panel.busy(now)`（Agent 攒消息、等模型时每圈调；大脑收到聊天事件到这一轮结束）
- **读一帧**：按 C 后连续截图，直到 `reader.panel_visible()`（最多 `open_timeout` 1.5 s），再拿那一帧 `reader.read()`；
  这一帧的结果照常交给 Agent / 身体（和平时读到的消息走同一条路），不单独处理
- `mode = "always"`：没有闲着 / 看一眼 / 等气泡，永远是"聊天中"且不会因安静关掉 —— 行为和现在一样
- 定时的起点是"上次读到面板的时间"（面板开着的每一帧都算读过），所以聊天中 → 闲着之后要再过 30 秒才第一次看一眼

## 2. 触发"看一眼"

| 触发 | 条件 | 进入 |
|---|---|---|
| 定时 | 距上次读面板 ≥ `idle_peek`（30 s） | 看一眼 |
| 好友头顶冒气泡 | 感知层认出 `typing` 气泡，挂在认出名字的好友身上（团子自己的已按团子框排除）；`bubble_strangers = true` 时陌生人的也算 | 等气泡 |
| 好友来了 | 大脑模式：身体的 `arrive` 事件；普通模式：`env.nearby()` 比上一圈多了人 | 看一眼 |
| 有人走近 | `approach` 事件（要打开感知层） | 看一眼 |
| 大脑要看聊天 | `chat_log` 工具在闲着时被调用：同步看一眼再返回 | 看一眼 |

- **为什么气泡要等**：气泡是对方**还在打字**时出现的，发出去消息才进面板；一看到就读、没读到就关，大概率刚好错过
- **防抖**：两次看一眼至少隔 `peek_cooldown`（5 s），触发在冷却中就记下来、冷却完再看；定时不受冷却影响（本来就隔 30 s）
- **黑屏 / 切场景**（身体的 `blackout`）时不看，按了也打不开；画面恢复后补看一次
- **借出期间不看**；这期间到过定时或出现过触发，就在归还后立刻补看一次（按最强的那个触发：有气泡就等气泡）
- **打不开**（按了 C 1.5 s 内没看到面板，比如被别的界面挡住）：记 WARNING、回闲着，下个周期再试，不连按
- **输入框开着**时不按 C（会打出字母 c）：说明团子在说话，本来就该是聊天中；若状态不是聊天中，改判成聊天中

气泡的来源：`PerceptionWatcher` 加一个 `typing_friends(since) -> list[str]`（`since` 之后头顶冒过气泡的好友名字，
复用 `_watch_typing` 已经挂在轨迹上的 `typing_at`）；`bubble_strangers` 时另查 `_typing` 里不是好友的记录。
`EnvWatcher`（没开感知层）返回空列表 —— 这时只有定时和 `arrive` 两种触发。

## 3. 借面板：`borrow()` 与现有代码的迁移

```python
with panel.borrow("camera"):   # 面板开着就按 C 关掉并等它消失；本来就关着什么也不按
    ...                        # 转镜头 / 换轮盘 / 点屏幕……
# 归还：借出前是聊天中（或 always 模式）→ 重新打开；闲着 → 保持关着（省一次按键）；
#       借出期间欠着的看一眼 → 立刻补
```

- **可嵌套**：计数，最外层归还才恢复（转镜头途中换轮盘，不会中途开面板）
- **只在身体线程 / Agent 主线程里调**（大脑的工具经命令队列也在身体线程执行）
- **重开失败不原地连按**：归还时重开一次，没开成就交给 `tick()` 按 `log_reopen_cooldown` 重试。
  这替代现在 `maybe_reopen` 的"关了 `log_reopen_after` 秒就重开"；auto 模式下只在"该开"的状态（聊天中）才重开
- `borrow()` 返回时带一个 `was_open`（借出前面板是不是开着），`Camera.spin` 的 `panel_reopened` 这类结果照旧能算
- **always 模式下借 = 现在的行为**（关 → 做事 → 重开），迁移本身不改默认行为

| 位置 | 现在 | 改成 |
|---|---|---|
| `brain/camera.py` `_ready()`（转镜头、`spin`、`around`） | 自己按 C 关 / 开 | `borrow("camera")`；关输入框（BACK）那一步留在 camera 里、在借之前做 |
| `game/emotes.py` `_panel_closed()`（换轮盘） | 同上 | `borrow("emotes")` |
| `game/social.py` `accept()` | 点屏幕顺带关面板，最后 `_reopen_panel()` 连按两次 | 整段包进 `borrow("social")`，删掉 `_reopen_panel` |
| `game/friendtree.py` | 同上 | `borrow("friend_check")`，删掉 `_reopen_panel` |
| `brain/skills.py` `SkillRunner` | — | `Skill.needs_camera = True` 的技能：开始时借、结束（done / failed / 被叫停 / 退出）时还；目前没有具体技能，只留接口 |

这几个类构造时不再收 `panel_visible` 和 `panel_key` 两个参数，改收 `panel`（`PanelManager`，测试里用假的）。
`social.py` 的 `accept()` 里点屏幕本身会关面板，借的时候面板可能已经被关了 —— `borrow` 进入时先看一眼再决定按不按，归还时同样先看再按。

## 4. 团子说话

- **说话前面板要开着**：`say`（大脑）、Agent 发送、`sender.type_ahead` 提前打开输入框 —— 这三处先调 `panel.before_speak()`：
  闲着 / 看一眼 / 等气泡 → 打开面板、进聊天中；借出中 → 不开（说话照常，归还后按聊天中恢复）。然后才按 Enter
- 发完照常 BACK 关输入框，面板留着；安静计时从这一刻清零
- 顺序固定成"先 C 再 Enter"：输入框开着时按 C 会打出字母 c

## 5. 事件、告警、意外开着

- 身体的 `panel` 事件（"面板关了半分钟，自动重开没成功，现在读不到聊天" / "又开了"）和 `look_around` 之后"聊天记录面板没重新打开"：
  **只在应该开着的时候发**（聊天中、不在借出中）。闲着时面板关着是正常的，不能叫醒大脑
- `ChatReader.panel_closed_since` 照旧记录（感知层靠它判断要不要跳过左边），但 `PANEL_LOST_AFTER` 只从"该开却没开"时算起
- **意外发现面板开着**（闲着时，比如用户在电脑前手动按了 C）：当作进入聊天中，读到的照常处理，安静 `quiet_close` 秒后自动关，不马上抢着关
- 退出（`shutdown`）：保持现在的收尾（停技能、复原镜头、换回轮盘），最后**把面板恢复成打开**，和用户接手时的习惯一致

## 6. 配置 `[panel]`

```toml
[panel]
mode = "always"        # "always" = 现在的常开；"auto" = 本设计的按需打开（真机验收后改默认）
idle_peek = 30.0       # 闲着时多久看一眼（秒）
quiet_close = 45.0     # 聊天中安静多久关面板
peek_cooldown = 5.0    # 两次看一眼至少隔多久
bubble_wait = 15.0     # 看到气泡后最多开着等多久
bubble_gone = 3.0      # 气泡消失后再等多久
bubble_strangers = false  # 陌生人的气泡也触发
open_timeout = 1.5     # 按 C 后最多等多久面板出现
```

`[vision]` 的 `log_open_key`、`log_reopen_after`、`log_reopen_cooldown` 保留原义（开面板的键、always 模式下关多久重开、重开的冷却）。
`config.example.toml` 同步加上这一节和注释。

## 7. 能看到它在干什么

- `agent.log` 每次状态切换一行 INFO：`面板：闲着 → 看一眼（定时）`、`看一眼：没有新消息，关上`、`面板借给 camera`、`面板：聊天中 → 闲着（安静 45 秒）`
- 可视化网页右栏加一项"聊天面板"：`聊天中` / `闲着（18 秒后看一眼）` / `等气泡（还剩 9 秒）` / `借出：camera`（`PanelManager.describe(now)`）
- 大脑提示词加一句："聊天面板平时关着，画面外的人说话可能晚半分钟才看到"（只在 auto 模式加）
- `runs/<…>/rows.log` 不变：面板开着的帧照常记，查漏读时对照状态切换的日志

## 8. 单元测试（`python -m pytest -q`，假设备 + 假时钟）

- 状态机每条转换：定时、各种触发、气泡等待（读到 / 消失 / 超时）、冷却中的触发延后、安静 45 秒关、意外开着、黑屏时不看、打不开时回闲着
- `busy()` / 输入框开着 / 团子说话都会清零安静计时
- `borrow`：嵌套；闲着归还不开、聊天中归还重开；借出期间的触发归还后补看；重开失败交给 `tick()` 重试；面板已被点屏幕关掉时不多按
- **always 模式和现在一致**：camera / emotes / social / friendtree 原有测试改成走 `borrow` 后照样通过
- `before_speak`：闲着时先 C 后 Enter；借出中不按 C
- 闲着时不发 `panel` 事件；聊天中关了半分钟照旧发
- `PerceptionWatcher.typing_friends()`：好友、陌生人、团子自己的气泡分别怎么算

## 9. 真机验收（`[panel] mode = "auto"`，全部通过才改默认）

| 检查 | 通过标准 |
|---|---|
| 好友站在画面外说话 5 次 | 5 次都读到，每次 ≤ 35 s |
| 好友走到身边后打招呼 | 读到，进聊天中 |
| 闲着 / 聊天中各做一次转镜头（`look_around`）、换轮盘、接互动 | 结束后面板状态对：闲着关着、聊天中开着 |
| 连跑 10 分钟 dry-run | 0 次面板关着时打出字母 c；对照 `rows.log` 0 次漏读 |
| 聊天中停下不说话 | 约 45 s 后面板自动关 |
| 闲着时大脑主动说话 | 先开面板再发，对方回复立刻读到 |

结果写进 `docs/game-ops.md` §3，并把 `mode` 默认值改成 `"auto"`、CLAUDE.md 相应说明一起改。

## 10. 依赖和不做的

- **气泡触发要等 `typing` 类补数据重训**（二期设计 §3；现在没有标注）。在那之前闲着时只靠定时、`arrive`、`approach`（后者要打开感知层），第一版不等它
- 不做"技能中途暂停、让路读聊天"：等真有长时间跟随再说
- 不做气泡 OCR
- 不改 `ChatReader` 的读法和对齐逻辑

## 11. 以后再说

- **界面状态识别**（单独的子项目，用户另开 agent 设计）：统一回答"现在开着哪些界面"（聊天面板、动作栏、设置、好友树、轮盘编辑、弹出确认框……），
  每种用最便宜可靠的办法认，只有位置和内容都不固定的弹窗考虑 YOLO 类别。做好后 `PanelManager` 的 `panel_visible()` / `ime_shown()` 换成它，接口不变
- 长技能期间定时让路读一眼聊天
- 按对话热度自动调 `idle_peek` / `quiet_close`
