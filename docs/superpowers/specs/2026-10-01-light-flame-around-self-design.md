# 点亮陌生人：在团子周围找火焰（设计）

日期：2026-10-01 晚。改的是 `docs/superpowers/specs/2026-10-01-light-unlit-stranger-design.md` 的 §2~§4（找黑影、判点亮），
举蜡烛（按 3）、鞠躬、蜡烛开关规矩、大脑能关这些都照那份 spec，不重复。

## 0. 为什么改（10-01 晚真机，三次）

原做法是"先靠 YOLO 找到黑影，再在他身上找火焰"。今晚三次 live 都没点成，每次都卡在 YOLO 认人这一环：

| 时间 | 现象 | 卡在哪 |
| --- | --- | --- |
| 22:06（`runs/20261001-215011-live-brain`） | 黑影站在身边 30 多秒，火焰匹配常到 0.86~0.99 | 火焰外环的"够暗、没白圈"把他举蜡烛时的白圈帧、半透明圆盘透出亮背景的帧都刷掉（已修：`e4f26ad`，`disk_sure`） |
| 22:31（`…-222836-live-brain`） | 黑影举着蜡烛站在团子旁边 | YOLO 认成 `player`（0.68）不是 `player_unlit`，不去找火焰（已修：`40038c0`，判成陌生人的 player 也找） |
| 22:48~22:52（`…-224317-live-brain`） | 四次黑影带着火焰到身边，只出了一次请求 | 晚上暗场景 YOLO 框不出黑影：0.27 / 0.28 的框被丢掉、火焰在框的搜索范围外、或者干脆没框 |

唯一那次举了蜡烛（22:50:41），8 秒后判"还是黑的"放下；那 8 秒没存图，**不知道原地举蜡烛到底能不能点亮**
（录像 c 里那次点亮是 09-30 用户点了圆盘、团子跟着走过去点上的；原地按 3 这条路从没验证过）。
**10-02 用户确认：原地按 3 举起蜡烛就能点亮，团子不用动。**

另外两件已知的事（原 spec §1）：
- 游戏只在**能点到的距离内**的黑影身上显示火焰（深色圆 + 米白火焰；他举蜡烛时外面多一圈一闪一闪的白圈）
- 火焰消失**不一定**是点上了（录像 d：冒彩虹爱心的人到第 38 秒还是黑的）；点上 = 黑影显出衣服颜色（录像 c 第 35.5~37 秒）

## 1. 目标和成功标准

- 黑影走到团子身边、身上冒出火焰时，团子能**不依赖 YOLO 认没认出这个人**，在 3~5 秒内按 3 举蜡烛
- 点亮了鞠躬；他走开了 / 没点亮就放下蜡烛，不反复举
- **每次举蜡烛都留下图**，事后能看清：火焰在哪、他亮没亮、走没走
- 底线不变：**绝不点火焰圆盘**（点了团子会跟着人走）；误举一次的代价只是举 8 秒蜡烛再放下

## 2. 做法选择

**在团子周围直接找火焰**：火焰只在够近的黑影身上出现，所以"团子身边冒出火焰"本身就是信号，不需要知道是谁。
没选的：降低黑影的 YOLO 置信度门槛（完全没框的照样漏，低分框还会更乱）；重训 YOLO（要晚上录素材，也只是把前一种做得好一点）。

## 3. 找火焰（感知层）

每次 `process()` 里（代替现在的 `_watch_disks`），最多每 `DISK_EVERY`（0.3 s）找一次：

1. **团子在哪**：YOLO `self` 轨迹里分数最高的那条，最近 `self_max_age`（1 s）内有更新才用；没有就**这次不找**（宁可漏，不全屏乱找）。
   `self_box`（转圈认出的）、`self_roi` 不用：它们是固定区域，团子会被镜头带着偏（今晚团子横坐标在 1190~1590 之间）
2. **搜索范围**（团子框高 = H、横向中心 = cx）：横向 `cx ± light_area_x × H`，纵向从框上沿往上 `light_area_up × H` 到框底；裁到画面内。
   起始值 `light_area_x = 1.2`、`light_area_up = 0.6`，**实现前先用今晚的帧量**（§9）。团子自己的框不扣掉（黑影贴着团子站时火焰会压在团子框上，22:31:56、22:49:12 都是）
3. **匹配**：`find_flame(frame, area, flame, min_score)`：和现在 `find_disk` 一样的米白剪影 + 模糊 + 多尺度模板匹配，只是范围由调用方给；
   不看外环亮度、不看白圈（`e4f26ad` 的结论）。范围里只取最好的一处（一次只点一个人）
4. **排除**（落在这些地方的火焰当没看到）：
   - 好友的点火请求：这一帧每个**认出了名字的**名字标签（tag）下面那一块：`tag.x − 0.5 × tag.w` ~ `tag.x2 + 0.5 × tag.w`，`tag.y` ~ `tag.y + 4.5 × tag.h`
     （圆圈平时在标签上沿往下 2.23 倍标签高、好友举蜡烛时约 3.3 倍，game-ops §6）
   - 聊天记录面板开着时被它挡住的左边（同感知层别处的 `panel_visible` 处理）
5. **连起来**（感知层里一条"火焰线索"，没有人物轨迹 id）：这次的火焰离上次的位置不超过 `light_jump × H`（0.5）、且离上次看到不超过 `DISK_GAP`（1 s）→ 同一条，
   更新位置、`last`、`best = max(best, score)`；否则开新的一条（编号自增），`first = now`、`best = score`。超过 `DISK_GAP` 没看到就作废
6. **出请求**：这条线索 `now − first ≥ light_after`（3 s）且 `best ≥ disk_sure`（0.85）、不在冷却里、没有正在进行的点亮 →
   `requests[LIGHT_KEY] = Request(STRANGER, LIGHT, 位置, now, track=线索编号)`，第一次出时 INFO "身边有没点火的陌生人：火焰出现了 3 秒"；条件不满足就把这个键删掉
7. **DEBUG 日志**（每秒最多一行）：火焰在哪 / 分数 / 线索编号和已持续多久 / best；没找的原因（没有团子框、在冷却、正在点亮）；被排除的原因（好友标签下、面板挡着）

## 4. 举蜡烛之后

身体 `_watch_light` 照旧（`clear_view`、`min_gap`、输入框 / 互动请求避让、按 3、`_raised`），接口改成按线索编号：

- `env.mark_tried(线索编号)`：记下举蜡烛的时刻、火焰最后的位置和大小 `r`、**这时他有多黑**（下面的 `black()`）；开始一次"点亮中"，删掉请求、期间不出新请求；开始存图（§5）
- `env.lit(线索编号, since) -> True / None / False`，身体每圈问一次：
  - 举起不满 `lit_min`（2 s）、感知暂停中、最近一帧太旧（> 0.5 s）→ `False`（还在等）
  - 火焰还在（线索没作废）→ `False`
  - 火焰消失超过 `DISK_GAP` 后，在**它最后的位置附近**找人：检测器这一帧给的 `player` / `player_unlit` 框（含低于正常门槛、≥ 0.2 的低分框，晚上黑影分数低）里和
    "火焰位置往下的一块"（横向 `±2r`、纵向 `−2r ~ +8r`，火焰在胸口或头顶）重叠最多的那个
    - 找到人、他的 `black()` 比举蜡烛时降了 `lit_drop` 以上且低于 `lit_black` → `True`（点亮了）
    - 找到人但还黑着 → `False`（接着等，到 `light_timeout` 放弃）
    - 没找到人 → `None`（他走了）
- `black(frame, box)`：人物框中间一半宽、上 70% 高里"很暗"像素（HSV 的 V < `lit_v`）的占比。黑影 ≈ 高，点亮后有衣服颜色 ≈ 低。
  `lit_v` / `lit_black` / `lit_drop` **实现前先在录像 c 第 30~40 秒（真的点亮了一次）和今晚的帧上量**（§9），量不出明显差别就退回"火焰消失 + 那里有人"，并在 spec 里记下来
- 身体收到：`True` → 原样（`accepted` 事件、`_schedule_bow`）；`None` → 记 INFO "他走开了"、按 3 放下（照旧只在自己刚举起、之后没做过动作时按）、不鞠躬；
  `light_timeout`（8 s）还没结果 → 照旧放弃放下。三种结果都调 `env.light_done(结果)`，结束"点亮中"、写存图的 `summary.json`
- 别的结局也要调 `light_done`，不然"点亮中"一直挂着、再也不出请求：举着时做了别的动作 / 接受了别的互动（蜡烛已经放下）→ `"interrupted"`；
  dry-run（`mark_tried` 之后不按键）→ 当场 `"dry-run"`；退出时还在点亮中 → `"exit"`
- **冷却**：认不出是谁，所以按时间冷却：结果不是点亮 → `light_cooldown`（60 s）内不出新请求。点亮了不冷却（点亮的人身上不会再有火焰）

## 5. 留证据（`runs/<…>/light/<HHMMSS>/`）

- 出请求那一刻存一张，`mark_tried` 起到 `light_done` 每 `diag_every`（0.5 s）存一张，一次最多 `diag_max`（30）张、一次运行最多 50 次；
  感知线程里存（它手上有帧）。dry-run 也存出请求那一张（不按键，但能看出"该不该举"）
- 图上画：搜索范围（灰）、团子框（白）、火焰（青圈，带分数）、判点亮时找到的人框（绿 / 紫，带 `black()`）；文件名带举起后第几秒
- `summary.json`：线索编号、出请求时间、举起时间、结果（lit / gone / timeout / 中途被打断）、举起时和结束时的 `black()`、火焰最后看到的时间
- 不开感知层、没有运行目录时不存

## 9. 实现前先量（离线，脚本放 `tmp/`，不进 git）

- **搜索范围**：今晚的帧（`tmp/lightdbg/w_*.jpg` 约 300 张 + 三次运行的 `hard/`），人工标出火焰和团子框，算火焰相对团子框的位置（以框高为单位）的分布，
  `light_area_x` / `light_area_up` 取能盖住全部真火焰的最小值再放宽 10%；同时数一下范围内灯笼等误匹配的最高分（应 < 0.85）
- **判点亮**：录像 c 第 30~40 秒那个黑影的框（YOLO 或手标），逐帧算 `black()`，看点亮前后差多少；今晚举蜡烛前那几张黑影的 `black()` 作对照
- 结果写进 game-ops §6，数字写回配置默认值

## 11. 真机验证（晚上）

1. 先 `run --dry-run --view`：黑影来到身边，日志里 3~5 秒内出"身边有没点火的陌生人"，`runs/<…>/light/` 里有图；网页上看得到火焰框
2. `--live`：原地举蜡烛能点亮（10-02 用户确认），看存下的图记下多久点亮、判点亮有没有晚 / 漏，定 `light_timeout`、`lit_*`
3. 黑影走开的情况：日志"他走开了"、蜡烛放下、没鞠躬
4. 好友举蜡烛给团子点火时团子不会误举（好友标签下的火焰被排除），接受点火照旧

## 12. 风险

- ~~原地举蜡烛可能根本点不亮~~：10-02 用户确认能点亮
- 团子框认不出时不找：YOLO `self` 今晚分数 0.5~0.75，大多认得出；认不出的时段会漏
- 不知道是谁：同一个黑影没点亮 60 秒后又在身边，会再举一次（每分钟最多一次，可以接受）
- 两个黑影同时在身边：一次只点最像的那个，点完（或冷却完）再点下一个
