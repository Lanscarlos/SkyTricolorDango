# 光遇 AI 伙伴 · 架构思路方案 v0.1

## 1. 目标

实时感知光遇画面中的好友、陌生人、聊天气泡和互动请求，由 LLM 理解并作出回应（回复消息、接受互动、跟随好友等）。

## 2. 总体架构

```
截屏采集
  → 感知层（YOLO + OCR + 模板匹配）         ← 身体·感官
  → 世界状态层（追踪、汇总、生成事件）
      ├→ 反射层（规则，快速响应）           ← 身体·反射
      └→ 大脑（LLM + 记忆 + 人设）          ← 大脑
  → 执行层（意图 → 模拟输入 → 感知验证）      ← 身体·手脚
```

核心原则：
- **LLM 不接收逐帧信号**，只接收汇总后的事件。
- **LLM 只输出意图**，不直接操作按键。
- **固定反应走反射层**，只有需要理解或生成内容的事才交给 LLM。

## 3. 模块说明

### 3.1 采集层
- PC 版：`dxcam`（或 `mss`），目标 30fps
- 手机：scrcpy 投屏后截屏

### 3.2 感知层

| 任务 | 方案 | 说明 |
|---|---|---|
| 角色检测 | YOLO（`friend` / `stranger`） | 自训练，转视角时的模糊帧要多标注 |
| 聊天气泡、名字标签 | YOLO（`chat_bubble` / `name_tag`） | 和角色放在同一个模型里 |
| 文字识别 | PaddleOCR 识别模型 | 只识别裁剪出的小图，跳过整图检测 |
| 互动请求（抱抱、牵手等） | 检测 UI 图标 | 模板匹配或 YOLO，不做动作识别 |
| 固定 UI 元素 | 模板匹配 | 零训练 |
| 场景/地图 | YOLO-cls 分类整张画面 | 低频运行即可（如每秒 1 次） |
| 目标追踪 | BoT-SORT（带相机运动补偿） | 适当调大 `track_buffer`，应对转视角 |

### 3.3 世界状态层

**实体表**（每个追踪目标一条）：
```
track_id, 类型(friend/stranger), 名字, 屏幕位置, 首次出现, 最后出现
```

**事件**（统一格式，推送给反射层和大脑）：
```json
{ "type": "chat", "who": "好友A", "track_id": 12, "text": "去跑图吗", "ts": 1727500000.12 }
```

事件类型（初版）：`entity_enter` / `entity_leave` / `chat` / `interaction_request` / `scene_change`

处理规则：
- 名字 OCR：每个 track_id 识别一次，结果缓存。ID 断开后，再用名字重新关联到原来的实体。
- 气泡：裁剪图哈希变化才重新识别。可以多帧投票，取最清晰的一帧。
- 防抖：目标离开画面超过 N 秒才触发 `entity_leave`。

### 3.4 反射层
规则示例：
- 好友发起牵手或抱抱 → 自动接受
- 陌生人发起互动 → 忽略，或交给大脑决定
- 所有事件 → 写入日志和记忆

### 3.5 大脑（LLM）
- **输入**：当前事件 + 画面内实体摘要 + 与该好友的近期对话记忆 + 人设
- **输出**（结构化意图）：
```json
{ "intent": "reply", "target": "好友A", "text": "好呀，去哪？" }
```
- **意图集**（初版）：`reply` / `accept_interaction` / `follow` / `stop_follow` / `ignore`
- **记忆**：每个好友单独保存对话历史和备注

### 3.6 执行层
- 把意图翻译成输入序列：PC 用 `pywin32` 或 `pydirectinput`，手机用 ADB
- **闭环验证**：执行后用感知层确认结果（比如聊天框是否打开、消息是否发出），失败就重试或上报
- `follow`：做视觉伺服，用 PID 让目标框保持在画面中央，不经过 LLM

## 4. 性能预算（每帧 33ms）

| 环节 | 预估 |
|---|---|
| 截屏 | 几 ms |
| YOLO 检测 | 独显几 ms；纯 CPU 需要用 YOLO26n、OpenVINO 并降低分辨率 |
| 追踪 | ByteTrack 可忽略；BoT-SORT 的运动补偿要几到十几 ms（CPU） |
| OCR | 按事件触发，平摊可忽略 |
| LLM | 0.5–3 s，异步运行，不阻塞感知循环 |

## 5. 迭代路线

1. **M1 感知可视化**：截屏 + YOLO + 追踪 + 叠加显示框和 ID
2. **M2 文字与身份**：气泡和名字 OCR，实体表能显示"谁是谁、说了什么"
3. **M3 事件系统**：世界状态层 + 事件日志（只记录，不回应）
4. **M4 反射与执行**：规则自动接受互动，打通执行层的闭环验证
5. **M5 接入大脑**：LLM 回复消息，加入好友记忆和人设

## 6. 待定事项

- [ ] 平台：PC 版还是手机投屏？
- [ ] 硬件：有没有 N 卡？这决定模型大小和推理后端
- [ ] LLM：本地部署还是调用 API？（要考虑延迟、成本和隐私）
- [ ] 是否提前告知好友有 AI 参与，还是让 AI 在对话里自己表明身份？（会影响人设和提示词）

## 7. 风险

- **封号**：自动操作和自动聊天可能违反游戏的用户协议。开发和测试阶段一律用小号。
- **识别稳定性**：暗色场景、光效、半透明气泡会影响效果，需要针对性补充数据。
- **误操作**：执行层必须有闭环验证和紧急停止热键。
