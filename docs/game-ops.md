# 光遇 × MuMu 操作手册（实测）

这里记录的是在真实游戏里验证过的操作方式和坑。坐标都是 **1920×1080 横屏截图** 下的像素，
代码里对应的归一化值在 `src/skydango/config.py`。标注"未验证"的是推测。

## 1. 输入通道：为什么要用 sendevent

MuMu 用的键位方案是 **「PC端操作方案」**：没有任何键位映射，`transparent_keyboard / transparent_mouse` 全开，
键盘原样透传给游戏，由**游戏自己**识别 PC 键位（Enter、C、E、Z、1~8……）。
（键位方案文件在 `%APPDATA%\Netease\MuMuPlayer\data\keymapConfig\com.netease.sky.vivo-*.json`。）

| 方式 | 游戏认不认 | 用途 |
|---|---|---|
| `adb shell input keyevent 66` | **不认**（虚拟按键设备） | 只用来发 Android 系统键，如 BACK(4) 关输入框 |
| `sendevent /dev/input/event4 1 <code> 1/0` | **认**（当成实体键盘） | 所有游戏按键 → `AdbDevice.hw_key / hw_key_down / hw_key_up` |
| `adb shell input tap / swipe / motionevent` | 认 | 点按钮、滚列表 |
| 鼠标设备 event3（`ABS_X/Y` 0~65535） | 注入后对轮盘无效 | 没用上 |

- 键盘设备是 **"Xiaomi Input"（`/dev/input/event4`）**，带 `KEY_ENTER`；代码会自动找（`getevent -pl` 里第一个带 KEY_ENTER 的设备）。
  adb shell 用户属于 `input` 组，可以直接写。
- 键码是 **Linux 键码**，不是 Android keycode：Enter 28、C 46、E 18、Z 44、数字 1~8 = 2~9。
- `getevent -p` 输出里键名后带 `*` 表示该键当前处于按下状态。遇到过 KEY_ENTER 卡在按下状态（之前某次漏了抬起），
  之后再按就没反应 → `hw_key` 每次先补发一个抬起。
- 长按：`hw_key_down` → 等待 → `hw_key_up`，**一定要记得抬起**。
- **键盘模式下的第一下触摸只切到触屏模式**（2026-09-27 更正：以前记成"被吞掉"），同时**会关掉聊天记录面板**，别的什么都不做。
  触屏模式的标志：左下角 (230, 847) 出现半径约 40 的灰色摇杆圈（圆环比内外侧亮 30~40，没有时接近 0；右下角 (1688, 847) 也有一个，但过一会儿会消失）。
  触屏模式下点击正常生效；之后按键**不会被吞**（按一下 C 就能开面板）。关键点击先看摇杆圈，没有就先点一下"唤醒"
- `wm size` 显示 1080×1920（物理竖屏），但截图和 `input tap` 坐标都是横屏 1920×1080，直接用截图坐标即可。
- 截图：`adb exec-out screencap`（raw RGBA）约 0.4 s/张，偶尔会连续超时 / 失败几秒（返回码 0xC0000142 等）。
  **MuMu 原生截图**：MuMu 自带 `shell/sdk/external_renderer_ipc.dll`（`nemu_connect(安装目录, 实例号)` →
  `nemu_capture_display`），约 9 ms/张，RGBA 上下颠倒，1920×1080 全分辨率 → `device/mumu.py`，`device.capture = "auto"` 默认启用，
  失败自动退回 adb。安装目录是含 nx_device / nx_main 的那一级（这台机器是 `D:\Program Files\Netease\MuMu`）；
  dll 会往 stdout 打印几行连接日志，无害。它读的是模拟器在电脑这边渲染好的画面，不碰游戏进程。
- 有了 9 ms 的截图，可以每 0.15 s 看一次；面板里的亮色像素（文字）没变就跳过 OCR（`chatlog.text_signature`），
  发现新消息的延迟约 0.2~0.5 s（原来 0.8~1.8 s）。

## 2. 界面状态与按键

| 键 | 作用 | 前提 / 备注 |
|---|---|---|
| Enter | 打开聊天输入框 | 输入框在底部 (15~1905, 962~1030)，占位文字"聊天……" |
| C | 开 / 关聊天记录面板（左侧） | 输入框开着时按 C 会打出字母 c |
| E | 开 / 关动作面板（右侧） | 同上 |
| 1~8 | 做快捷轮盘对应格子的动作 | **不需要按 Z**；输入框开着时会打出数字 |
| 长按 Z | 显示快捷轮盘（只是看） | **聊天记录面板开着时长按 Z 没反应** |
| 长按 Z 时按 E | 进入轮盘编辑界面 | 松开 Z 后编辑界面保持 |
| BACK（`input keyevent 4`） | 关掉输入框 / 软键盘 | |
| 减号 `-`（键码 12） / 加号 `=`（键码 13） | 镜头**拉近 / 拉远**（减号是拉近，和直觉相反） | **聊天记录面板开着时没反应**，要先按 C 关掉；小键盘的 ± 也没反应。实测按 3 次拉近 + 3 次拉远能回到原位 |
| 方向键 ←→（键码 105 / 106） | 水平转视角 | 测试时先关了面板（面板开着时有没有反应没试过，缩放是没反应的）；按住 0.5 s 约转 90°，再反方向按住 0.5 s 基本转回。**连续转一圈几秒、是否匀速、水平视野角、画面多模糊、靠墙时镜头的表现：待用 `python -m skydango camera spin` 实测**（结果填进 `[spin] seconds_per_turn` / `hfov`，写回这里） |
| 方向键 ↑↓（键码 103 / 108） | 调俯仰角：↑ 镜头压低到脚边往上看，↓ 抬回来 | 同上；来回各 0.5 s 基本复原（略有偏差） |
| W A S D | 移动角色，W 前进 / S 后退（Linux 键码 17 / 31，A/D=30/32 未测） | 2026-09-27 实测：聊天记录面板开着也有效（不用像镜头那样先关面板），`hw_key_down` 按住 0.3 s 几乎看不出移动，按住 **1 s 幅度很大**（从好友群里一路走到几米外的石塔根、踩进水里），马上反方向按 1 s 基本能走回原位。**幅度对时长很敏感，做移动能力时单次按键时长要控制得比这次测试短很多**（比如 0.2~0.4 s 一步，边走边看要不要停）；会松开牵手、走开会离开朋友身边 |
| Q | 呼喊，能看到屏幕外好友的名字（用户告知）；长按是大叫 | 面板开着时按了没反应。面板关着时按下，左边缘（约 (40,490)）出现一个眼睛图标并一直留着，**3 秒内没出现任何名字**（当时卡洛在画面里，老登可能也在附近）—— 名字怎么显示还没搞清楚。每喊一次好友都能看到，别乱喊 |

**发任何游戏按键前先确认输入框是关的**：`AdbDevice.ime_shown()`（读 `dumpsys input_method` 的 `mInputShown`）。
输入框开着时，所有字母数字键都会变成打字。

## 3. 聊天

### 发消息
1. 输入框没开 → `hw_key(28)`（Enter）打开。实测按键后约 0.07 s 输入框就出现（`ime_shown()` 变 True），不用固定等
2. ADBKeyboard 输入：`am broadcast -a ADB_INPUT_B64 --es msg <base64>`（支持中文，需 ADBKeyboard 为当前输入法）
3. 提交：`am broadcast -a ADB_EDITOR_CODE --ei code 4`（IME_ACTION_SEND）——实测有效
4. **发送后输入框不会自动关闭**；输入框开着时**自己头顶会一直显示"正在输入"的气泡** → 发完用 BACK 关掉
   （`sender.close_with_back = true`）。关掉后聊天记录面板保持打开，面板变高（见下）
5. 反过来利用这一点：**等模型回复时先按 Enter 打开输入框**（`sender.type_ahead`），头顶就显示"正在输入"，像真人在打字；
   发送时省掉打开这一步。模型决定不回复就按 BACK 关掉（只关自己打开的，输入框本来开着就不碰）

头顶气泡显示有延迟：先显示"正在输入"的 `..`，几秒后才出文字；连发几句会排队依次显示。

### 读消息：聊天记录面板（C）
- 位置：左侧 x 0~640，下面是面板自带的"聊天……"胶囊输入框。**面板高度随输入框开关变化**：
  - 输入框关着：胶囊上沿 y≈1006，最新一行在 y≈930~980
  - 按 Enter 打开输入框：整个面板上移约 75 px，胶囊上沿 y≈932，底部再叠一条全宽的浅色输入栏（962~1030）
  - 所以固定的读取区域总会在一种状态下切掉最新一条 → 每帧找胶囊，读到它上面 4 px 为止（`chatlog.find_input_top`）；
    找不到时退回 `vision.log_roi = [0, 0, 0.335, 0.855]`
  - 胶囊是空心框：上沿是横贯面板的细亮线（关着白色、开着蓝色，2~4 px），线上线下都暗，往下 57~60 px 还有下沿。
    **坑**：自己发的长回复是几乎横贯面板的浅色气泡，它的下沿也是"亮线、下面变暗"。只按这一条找的时候，
    气泡一落到面板下半部分就被当成输入框，下面的新消息全读不到，要等气泡被顶上去才一下子冒出好几条（实测漏读十几秒）。
    现在要求细线（上方也暗）+ 有下沿，气泡两条都不满足
  - **胶囊会变暗**（2026-09-28 录像实测）：面板开着一会儿后描边变成暗灰（V≈84，外面贴一圈深色边、里面 V≈26），
    过渡中是 V≈159 / 里面 88。只按白线（V > 170）找时整段录像都判成"面板没开"，面板里的"内容 - 好友名"
    被弱标注当成了头顶名字标签。白线找不到时按相对亮度再找一次：两条比上下都亮 30 以上的细线、间隔约 60 px、中间整段暗
- 一行一条，**新消息在底部**，旧的往上滚；面板可以上下滚动，但保留的记录条数有限
- 别人的消息：深色半透明底 + 白色斜体，格式 **"内容 - 说话人"**，贴左边（x≈20 起）
- 自己的消息：**浅色米白气泡 + 深色字，贴右边，没有说话人**（靠背景亮度识别，中位数 V ≥ 150）
- **没解锁聊天的陌生人，内容被游戏替换成省略号**："........ - 陌生人"。OCR 常把省略号和"-"一起丢掉，只读到"陌生人"
  → 没有分隔符的行按"被屏蔽"处理。所以 Agent **只能和解锁了聊天的好友 / 长椅上的人对话**
- 面板关着时，3D 场景里的名字标签（如好友昵称）可能落在这块区域里 → 按排版过滤：别人的行必须贴左（x ≤ 面板宽 30%），
  自己的行必须贴右（x2 ≥ 面板宽 85%）
- 好友的真实文字消息（2026-09-27 实测）："你好，我是卡洛，你叫什么名字 - 懒洋洋大王"，内容是白色正体、名字是米黄色粗斜体，
  同一个深色底框里，OCR 读成一整行，按最后一个"-"拆分正确
- **长消息会在同一个深色框里折行**（一行约 20 个汉字，宽约 566 px），" - 名字"只在最后一行。
  折行之间几乎贴着（间距 0~2 px），不同消息之间隔 25~30 px → 上一行写满（≥ 面板宽 75%）+ 间距小 + 底色一致就拼成一条
  （`chatlog._merge_wrapped`）。不拼的话前几行会被当成"只有名字的被屏蔽行"，模型只看到最后半句

### 头顶气泡（不推荐）
米色半透明（HSV 约 H23 S33 V216），亮度就在阈值边上，还经常和白色角色 / 光效连成一片，形状过滤很难稳定。
保留在 `vision.mode = "bubble"` 作为备选。

## 4. 动作

### 动作面板（E）
右侧 x 约 1330~1800，4 列、列间距约 119 px。从上到下：
1. **最近使用**（图标右下角带时钟角标）
2. 聊天气泡图标
3. 道具：火、门、家园（？）、锁住的"?"
4. 铅笔图标（编辑）
5. 动作网格（很长，要滚动；图标上方的小圆点表示等级，不同等级是不同条目）

点动作网格里的图标就会做这个动作；再按 E 关闭面板。

### 快捷轮盘
- 普通状态（长按 Z）：轮盘在右侧，中心约 (1585, 335)，半径约 185
- **格子编号从正上方开始顺时针 1~8**；数字键 2 实测对应右上格
- 这台机器上的布局：1 鞠躬、2 张臂踢腿、**3 火（道具）**、4 害羞、5 站姿动作、6 欢呼（2级）、7 发抖、**8 门（道具）**
  —— 3、8 是道具，配置里默认锁定（`wheel.locked_slots = [3, 8]`）
- 在轮盘上点击 / 拖动 / 移动注入的鼠标都**不能**选中格子，只能用数字键
- 聊天记录面板（C）开着时按数字键**能**直接做动作，面板保持打开（2026-09-27 实测）—— Agent 做轮盘上的动作不用关面板。
  旁边有别人走动时，光靠截图很难看出是不是自己在做动作，要人在画面前确认

### 轮盘编辑界面（长按 Z + E）
- 轮盘移到左侧，中心 (643, 540)，格子中心半径约 195（0.18 × 高度）；正中间是 ✓；右侧是动作列表（同 E 面板，可滚动）
- **换动作：点列表里的动作（它会出现在轮盘中心）→ 点目标格子**。拖拽不行（长按拖动只会让图标缩一下，松手没效果）
- **修改实时生效**，没有"取消"
- **中间的 ✓ 只有改过东西后才能关闭界面**；右上角 **× (1888, 32)** 任何时候都能关 → 代码统一点 ×（带重试，见 §1 第一次触摸被吞）
- 编辑界面里按数字键会选中格子（格子下方出现一个 ×，推测是清空），**不要在编辑界面里按数字键**
- 列表滚动：拖 442 px 实际滚动约 400~420 px，没有惯性，不会跳行
- 轮盘里的图标约是列表里的 1.25 倍大；"2级"之类的字会叠在图标上

### 图标识别
- 图标是深色底上的米白色剪影、没有文字 → 只比较剪影（灰度 > 150 的形状），多尺度模板匹配
- 列表里找图标：同尺寸，命中约 0.95，找不到时最高只有 0.5 左右，阈值 0.8
- 读轮盘格子：阈值 0.72（图标更大、带字）；"火"图标带动画，有时认不出（0.5~0.9 浮动）
- 扫描动作列表（`emotes scan`）的坑：
  - "最近使用"里带角标的版本会把后面干净的版本判成重复 → 重复时保留剪影面积小的
  - 列表上下边缘的图标会被裁掉一截 → 只截离边缘 ≥ 60 px 的图标（翻页有 600+ px 重叠，不会漏）
  - 本机约 160 个条目

### 副作用
- **做动作会松开牵手**（实测两次：和好友牵手时做动作，手被松开）。自动做动作前要考虑这一点。
- 修改轮盘会改掉用户自己的配置，测试时先记下原状态，测完用 `emotes set` 恢复并 `emotes wheel` 核对。
- Agent 聊天时做动作（`game/emotes.py`）：轮盘上的直接按数字键；白名单动作要换轮盘，先按 C 关聊天记录面板、编辑完再按 C 打开，
  期间别人发的消息留在面板里，重开后照样读得到。启动时读一次轮盘（同样要关 / 开面板），退出时把 `swap_slots` 换回原样。

## 5. 识别环境（身边有谁、在哪）

- 3D 场景里好友头顶有名字标签（米白色字，约 40~50 px 高），OCR 置信度 1.00，例如 (1478,452) "番茄炒蛋盖饭"、(1298,462) "懒洋洋大王"。
  聊天记录面板开着时，站在左边的人的标签会被面板挡住
- 对面板右边 1280×960 的区域做 OCR 约 0.7~1 s；除了名字只有零星噪音（"●"、"2级"、"X" 这类图标字）
- 标签会被别的角色、特效挡住，同一个人不是每次都能读到 → 30 秒内看到过就算在旁边
- 进入新区域时屏幕上是否会显示地名：**未验证**
- 聊天记录面板是半透明的，站在左边的人的名字标签会叠在面板上（能看见），但扫描时为了不把面板里的“- 名字”误当成标签，面板区域不扫 → 这种情况认不到
- **陌生人和好友怎么区分**（用户告知，2026-09-28，未截图核对）：
  - 没点火的陌生人是**黑色剪影**，看不到外观；点火之后才显示外观，和好友看起来一样
  - 点过火之后只能靠**头顶的名字标签**区分（好友有，陌生人没有）
  - 另一个办法：**点一下那个人物**，右侧会打开好友树面板，看好友树就知道是不是好友。要点屏幕（会关掉聊天记录面板，见 §6）。
    **按 ESC 关闭面板**（用户告知，2026-09-28）。做成了大脑的 `check_friend` 工具（默认关）。
    **待核对**：面板在右边多大、好友和陌生人的面板有什么区别
    —— 用 `python -m skydango friend-check X Y` 点一个好友、一个陌生人各试一次，看 `tmp/friend-check/` 的截图，结论补在这里
- 镜头可以用减号 / 加号拉近拉远（见 §2，要先关面板）：拉远能看到更多人但字变小，拉近字大但视野窄。目前没用上
- **感知层三期的待测项**（代码已写，都**没在真机 / GPU 上验证**，测完把结论写在这里）：
  - 远处的人：框高不到屏高 8% 时名字标签有多大、头顶裁一块放大后 YOLO 能不能框到、OCR 读不读得出（`perception compare --far-crops 0` 和默认各跑一次对比）
  - 认地图：同一个地方不同角度 / 时间 / 天气的截图像不像（`places add` 每处截几张，`places bench` 看留一法的认对率）；
    进入新区域时屏幕中上部的地名提示仍未验证
  - 别人对团子做的动作：好友对着团子挥手、鞠躬时角色的动作幅度多大、2 秒够不够一个完整动作（`record --fps 8` 录下来看）

## 6. 好友发起的互动（牵手 / 拥抱 / 击掌）

2026-09-27 和好友实测（录像 + 两次点击实验）：
- 好友头顶名字正下方有个圆圈（中心约在名字上沿往下 98 px ≈ 2.23 倍标签高度，半径约 50 px），平时里面是 ✦。
  对方发起互动时换成对应图标：**两只手 = 牵手，两个小人抱在一起 = 拥抱，两个小人举手 = 击掌，一个背着另一个 = 背背**，
  对方一直举着，图标就一直在；取消后变回 ✦。好友之间圆圈样式有两种（描边圆环 / 深色实心），里面的图标一样
- 图标是米白色，按"亮 + 不饱和"取剪影匹配，能把旁边角色身上的黄绿色光排除掉；四种图标区分得很开（最低分 0.83）
- **点圆圈就接受**。键盘模式下第一下只会切到触屏模式（见 §1）→ 先看左下角有没有摇杆圈，没有就先点一下唤醒
- **真正生效的点击只能有一下**：牵上之后再点圆圈会松手。实测旧逻辑"原地没反应就补点"导致断手 ——
  好友站得近时团子几乎不用走，图标会原地停一会儿再消失，看起来像没点中
- 点中后团子**自己走过去**，走的这 1~2 秒里图标还在、位置在变 → 这时候别再点，等圆圈消失就是牵上了
- 牵着手时，对方头顶的圆圈消失
- 点屏幕会关掉聊天记录面板 → 接受完要按 C 重新打开；团子正在走 / 做互动时按了可能没反应，隔 1.5 s 再试
- 陌生人的点火请求还没录到；另外见过一个陌生人头顶有彩虹色心形图标，含义未知
- 实测（live）：拥抱、牵手、背背都是一次点击接上，发现请求到接上约 2~4 s（后台每 3 s 扫一次）
- 牵着手时好友会带团子走，途中出现过整屏黑、只剩角色和圆圈的画面（像切场景），这时聊天面板和其他界面都不见了、按 C 也没反应，
  过十几秒恢复 → 面板自动重开的冷却改成 10 s
